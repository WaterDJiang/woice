# Woice 录音落盘与 macOS UI 修复规格

## 目标

- 允许麦克风后，录音会话稳定开始，不因 CoreAudio 回调线程退出。
- 同一时刻只保留一个 Woice 进程和一个菜单栏入口。
- 单实例锁必须有回归测试，第二个同用户 Woice 实例在获取锁时直接退出，不创建第二个菜单栏入口。
- 录音结束后，原始音频可靠保存到 Application Support，并在历史详情显示文件状态。
- 设置与菜单栏界面符合 Quiet Native Utility：信息层级清楚、状态可见、操作可恢复。

## 范围

- `RecordingService`：权限、音频 Tap、文件写入、停止/取消和错误传播。
- `AppState`：录音生命周期、持久化确认、文件状态。
- `MenuBarPopover`、`HistoryView`、`RecordingDetailView`、`SettingsView`：布局、状态和可访问性。
- `Makefile` 安装流程：停止同一应用的旧进程，避免构建目录与 `/Applications` 同时运行。
- 测试：录音文件持久化/可读性、设置与 UI 状态契约、安装实例检查。

## 验收标准

- 点击“开始录音”并允许麦克风后，Woice 进程保持运行，状态进入“正在录音”，不产生崩溃报告。
- 点击“结束录音”后，`~/Library/Application Support/Woice/recordings/<uuid>.wav` 存在、可读取且文件大小大于 0。
- 录音记录在历史中显示时长、文件状态和原始音频路径；转写失败不能删除音频。
- `make install` 前只终止 Woice 自身旧实例，安装后 `pgrep` 只能找到一个 Woice 进程。
- 菜单栏 Popover 保持 336 pt；主动作只有一个；录音、处理中、等待确认、失败、已保存均有图标和文字。
- Popover 关闭时，菜单栏状态项仍显示录音图标与 `mm:ss` 时长；用户不需要保持 Popover 打开才能确认录音正在推进。
- 停止后“最近结果”同时显示本次有效录音时长和转写状态，复听入口仍在历史详情中。
- 录音、音频落盘或转写失败后，重新打开菜单栏 Popover 不得清除错误；错误应保留到下一次明确动作或成功状态，并说明下一步。
- 设置使用原生侧栏按“录音 / 服务 / 文件与隐私”分组，ASR/LLM 字段保留清晰标签、帮助文案、就地 URL 错误和保存结果反馈，可键盘操作。
- 麦克风权限被拒绝时，设置页在状态说明旁提供直达 macOS 麦克风隐私设置的恢复入口；不在打开设置时再次隐式申请权限。
- 首次启动在菜单栏内提供可关闭的三步承诺：录音由用户主动开始、原始音频先保存在本机、配置 API 后每次外发仍需确认；引导不阻塞主录音动作。
- `make verify`、实际安装和一次真实录音 smoke test 通过。

## 非目标

- 本次不引入 GRDB、WhisperKit、全局快捷键或本地 RPC。
- 不改变原始音频不可覆盖和云端外发确认规则。

## 影响面

- 代码：录音模块、状态模型、UI、安装脚本和测试。
- 数据：沿用现有录音目录；不删除已有录音。
- 发布：当前仍为本地 ad hoc 包，Developer ID 和公证另按计划处理。
