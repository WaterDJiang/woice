# 系统音频权限状态与真实采集可靠性

## 问题

- 用户已在系统设置允许屏幕录制，但 Woice 设置页仍显示“需要屏幕录制权限”。
- 权限状态误报会让会议模式无法启动系统音频，用户误以为系统声音采集没有实现。
- 当前开发包使用 ad hoc 签名，反复重装可能改变代码签名哈希，macOS TCC 可能把授权绑定到旧安装事实。

## 设计修正

- `SCShareableContent` 能否读取可共享显示器是系统音频链路的运行时主证据；`CGPreflightScreenCaptureAccess()` 作为权限提示辅助，不再单独短路成功路径。
- 若 ScreenCaptureKit 能读到显示器，即使 preflight 返回旧状态，也显示“系统音频能力可用”；若读取失败且 preflight 为 false，显示需要授权；若 preflight 为 true 但读取失败，显示具体不可用原因。
- 采集启动仅在运行时读取失败或目标为空后辅助读取 preflight：false 映射为可执行的屏幕录制授权提示，true 保留运行时错误/无显示器事实，不把无目标环境伪装成授权成功。
- 从系统设置返回 Woice 后自动刷新能力状态，避免用户必须重启窗口或重复点击。
- 请求权限后不立即用旧状态覆盖界面；按钮反馈说明“返回 Woice 后会自动重检”。
- 若用户从系统设置返回后，当前运行实例仍无法通过 TCC/ScreenCaptureKit 校验，状态改为“需要重新授权当前安装包”，明确说明系统设置中可能保留旧版 Woice 的授权；不继续显示含糊的“需要屏幕录制权限”。
- 若系统设置存在旧的 Woice 授权项，界面提示用户移除旧项后再对当前安装包授权；ad hoc 签名变化不会被伪装成运行时采集成功。
- 系统音频失败时保留麦克风 WAV，并把“权限失败 / 没有显示器 / 无有效音频 buffer”分开显示。

## 真实采集验收

- 运行时验证 ScreenCaptureKit 可启动、停止、收到 buffer 并保存 CAF。
- 在已授权当前安装包的 Mac 上播放系统声音样本，验证 `peakLevel > 0`、CAF 时长/帧数有效，并在录音详情页可复听。
- 自动探针不得把“收到静音 buffer”写成已捕获有效声音；静音源和无源场景要保留可诊断状态。

## 验收标准

- AC-001：系统设置已授权且 `SCShareableContent` 可读时，设置页显示“系统音频能力可用”，不再显示“需要授权”。
- AC-002：从系统设置返回后 1 秒内自动刷新状态；重新检查按钮仍可手动触发。
- AC-002a：请求权限后的轮询仍未获得当前实例采集能力时，设置页显示“需要重新授权当前安装包”及关闭/重新打开 Woice 的下一步，不把旧授权误报为当前实例已授权。
- AC-003：会议模式录音可在授权条件下保存独立 CAF；播放系统声音样本时 CAF 峰值大于 0，并可在详情页复听。
- AC-004：权限无效、可共享显示器为空、流启动失败和无音频 buffer 均显示明确下一步，不删除麦克风 WAV。
- AC-005：`make docs-check`、`make harness-check`、`make lint`、`make test`、`make verify` 和安装包启动通过。

## 边界

- ad hoc 开发包可能因重新签名导致 TCC 授权需要重新确认；正式发布必须使用稳定的 Developer ID/团队签名。
- DRM/受保护媒体、远程桌面无可共享显示器和输出设备静音不保证能得到有效音频峰值。
