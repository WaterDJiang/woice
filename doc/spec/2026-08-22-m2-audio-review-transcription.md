# Woice M2 音频复听与转写闭环规格

## 目标

- 用户能在历史详情中播放、暂停、拖动和查看原始录音时长。
- 打开历史详情即显示已提交音频的真实总时长，不要求先点击播放才读取元数据。
- 录音状态和文件事实一致：时长、文件大小、音频可读性和播放状态可见。
- 用户可在设置中填写任意 OpenAI-compatible Audio Transcriptions API，保存后可对录音发起转写。
- 设置页以主流 macOS 工具的侧栏分组、健康状态和可恢复错误为基线，不把 API 配置藏在复杂流程中。
- 设置编辑必须能区分“当前草稿”和“已保存事实”，提供还原未保存更改，避免用户误以为 API/权限选项已生效。
- 为 M2 会议能力保留稳定边界：音频回放、时间位置、转写结果是后续实时转录/双音轨的输入契约。

## 范围

- `AudioPlaybackService`：本地 WAV 播放、暂停、停止、跳转、当前时间和总时长。
- `RecordingDetailView`：播放器控件、音频事实、转写入口和处理状态。
- `AppState`：播放状态与当前记录绑定、转写任务反馈、失败恢复。
- `AppState`：ASR 成功后可按需生成 Markdown 笔记；LLM 失败显示可恢复状态，不影响原文和音频。
- `SettingsView`：侧栏分组、ASR/LLM 配置状态、Keychain 状态、输入校验和隐私文案；不做未经用户触发的网络探测。
- 测试：音频文件可读性、播放器状态、OpenAI-compatible 请求契约、AppState 自定义 ASR 端到端、真实 Mac 安装验收。

## 验收标准

- 选中一条已保存录音，点击播放后能听到音频；暂停、继续、停止和拖动位置有效，时长显示与文件时长一致。
- 音频文件不存在、无法读取或播放失败时，界面显示原因和下一步，不崩溃、不删除原始文件。
- ASR 或 LLM 失败时，详情页保留原始录音/原文并提供对应重试入口，不把失败记录伪装成成功。
- ASR Endpoint、模型、语言和 Keychain 密钥可保存；配置空缺或 URL 非 HTTP(S) 时，在设置页对应字段就地提示，保存失败不会显示虚假成功。
- 修改设置后侧栏显示分组健康摘要；存在未保存更改时可还原草稿，成功保存后才显示已保存状态。
- 当 ASR/LLM Endpoint 已配置时，模型字段为必填；模型为空必须在对应字段就地报错并阻止保存。
- 对固定 OpenAI-compatible Fixture，转写请求包含 WAV、模型、语言和授权头；成功原文写入历史，失败保留原始音频并允许重试。
- `make verify` 通过；Release 安装后只有一个 Woice 实例；真实权限下完成一次录音、播放和自定义 ASR 转写 smoke test（服务端用隔离 Fixture 验证请求契约）。

## M2 顺序

- M2-03a：先完成本地音频复听和时间位置契约。
- M2-03b：再接入真实转写 Provider 健康度和可重试任务。
- M2-01：在上述契约稳定后接入系统音频 + 麦克风双音轨，不把采集权限和回放 UI 混在一起。
- M2-02/M2-03：随后加入实时预览、VAD、时间戳、摘要和待办。
- M2-04 至 M2-07：按计划推进自动粘贴、PI、TTS 和受控进程 Provider。

## 非目标

- 本轮不引入 GRDB、WhisperKit 或新的音频第三方依赖。
- 不默认启动系统音频采集，不绕过用户手势和外发确认。

## 影响面

- 数据：沿用现有 WAV 和 JSON 索引；不覆盖原始音频或原始转录。
- UI：历史详情新增播放器；设置页使用原生侧栏导航，按录音/服务/文件与隐私分组，并增加保存成功/失败和配置状态反馈。
- 发布：仍使用当前 SwiftPM ad hoc 包，签名/公证按 M1 发布门槛处理。
