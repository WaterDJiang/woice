# M2-02 VAD 与分段状态基础

> 状态：基础实现完成，声音片段已持久化，实时 ASR 待后续  
> 创建日期：2026-08-22  
> 关联计划：[`2026-08-22-m0-mvp.md`](../plan/2026-08-22-m0-mvp.md)

## 1. 目标

把“有麦克风帧”和“检测到有效声音”区分开，为实时转写、时间戳和会议摘要建立确定性的音频活动状态。此工作包不把 VAD 结果当成转写文本，也不引入模型 SDK。

## 2. 范围

- 在录音写入边界计算每个 PCM buffer 的峰值和帧时长。
- 使用固定阈值与静音 hangover（600 ms）判定 `等待输入 / 检测到声音 / 暂时安静`。
- 以声音重新出现作为新片段起点，记录已检测片段数量、当前片段时长和可供后续 Job 消费的起止时间。
- 录音状态卡用用户语言显示“已接收帧”和“检测到声音/当前安静”，帮助诊断无声录音。
- 通过纯状态机测试覆盖阈值、hangover、片段计数和时长，不依赖真实隐私音频。

## 3. 不在本工作包

- 不把声音活动判定直接写成 Transcript。
- 不承诺说话人分离、中文语音识别准确率或实时模型速度。
- 不替换当前原始 WAV/CAF 落盘；分段文件和增量转写在后续工作包实现。

## 4. 验收标准

- 低于阈值的输入不会被标记为有效声音。
- 连续有效声音只计为一个片段；静音超过 600 ms 后再次有声会开启新片段。
- 当前片段时长和片段数量来自实际 PCM 帧，不使用 UI wall-clock 估算。
- `AudioActivitySnapshot.segments` 返回已关闭片段和当前片段的相对时间范围，后续可直接映射到分段转写 Job。
- 录音停止时将已检测的声音时间范围保存为 `RecordingRecord.voiceSegments`；详情页可点击片段跳转到原始 WAV。
- 录音 UI 同时显示麦克风帧状态、电平和 VAD 状态；无声时明确说明下一步。
- `make verify` 通过，现有真实麦克风、系统音频、API、时长和复听测试不回归。

## 5. 后续接口

下一工作包可以消费 `AudioActivitySnapshot` 生成已关闭音频分段，并将分段交给可重试的 ASR Job；原始音频仍不可覆盖。
