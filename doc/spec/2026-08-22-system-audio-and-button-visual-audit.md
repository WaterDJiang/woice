# 系统声音采集与按钮视觉审计

## 目标

在保持 Woice“安静的原生 macOS 工具”定位的前提下，吸收参考截图中清晰的主次按钮层级，补齐全局按钮的尺寸、按下态和图标语义；同时明确并验证会议模式是否能采集正在播放的视频、会议应用或其他系统声音。

## 用户需求

- 录音按钮应是工作台唯一的主动作，图标、文字、颜色和录音中状态一眼可辨。
- 搜索、清除选择、复制、粘贴、刷新、设置和退出等动作应使用统一的次级按钮规则，不应看起来像多个同等主入口。
- 所有可点击按钮需要有足够的点击区域、hover/pressed/disabled 反馈、帮助文本和 VoiceOver 可读名称。
- 用户开启会议模式后，应知道麦克风和系统声音是两条独立轨道，并能看到权限、采集进行中、没有声音和失败等状态。

## 技术结论

- Woice 当前使用 ScreenCaptureKit 的 `SCStreamConfiguration.capturesAudio` 捕获系统音频，使用 AVAudioEngine 保存麦克风 WAV。
- 系统音频保存为同一录音 ID 对应的独立 CAF；停止录音后可在详情页单独复听。系统音频失败时不删除麦克风轨道。
- 系统声音采集需要 macOS“屏幕录制”权限和可共享显示器。它可以覆盖正在播放的视频、会议应用和桌面混音；受 DRM/受保护内容、远程桌面无可共享显示器、应用自身音频排除策略影响的内容不保证可捕获。
- Woice 不默认录制系统声音；只有用户显式打开“录制系统音频（会议模式）”并开始录音时才启动 ScreenCaptureKit。
- 采集能力检查不等于已经录到声音。最终事实以停止后 CAF 是否存在、buffer 数量、时长和峰值为准。

## UI 设计规则

- 主动作：开始录音/结束录音使用 `.borderedProminent`，开始为系统强调色，录音中切换为语义红色；保留 `mic.fill`/`stop.fill` 和文字。
- 次动作：工具栏和工作区操作使用统一的 `WoiceBorderlessButtonStyle`，最小点击区域 32 pt，圆角背景仅在 hover/pressed 时出现；不把所有按钮渲染成厚重胶囊。
- 工具栏图标：图标 15–16 pt、按钮内容区域不小于 32×32 pt；仅图标按钮必须有 `help` 与 `accessibilityLabel`。
- 状态反馈：按下态在 120 ms 内出现；异步动作显示进度或禁用态；成功/失败同时使用图标、文字和语义色，不仅依赖颜色。
- 深色模式：沿用系统材质和语义色，不复制参考截图的纯黑背景；蓝色只表示主动作/进行中，红色只表示录音中、错误和破坏性操作。

## 验收标准

- AC-UI-01：工作台、菜单栏 Popover、设置页、录音详情页的按钮至少有 32 pt 可点击区域；主录音按钮与次级动作在尺寸、颜色和文案上有明确层级。
- AC-UI-02：复制原文、粘贴、刷新、清除选择、模型操作和设置保存点击后均显示按下态与成功/失败反馈；禁用按钮不会显示成功反馈。
- AC-UI-03：图标按钮可通过 VoiceOver 读出动作名称，hover 时有帮助文本；Reduce Motion 开启时不播放缩放动画。
- AC-AUDIO-01：未授权时设置页明确显示需要屏幕录制权限，并提供请求和重新检查动作；不自动启动系统音频采集。
- AC-AUDIO-02：开启会议模式并开始录音时，界面同时显示麦克风状态和系统声音状态；系统声音启动失败时保留麦克风录音并给出下一步。
- AC-AUDIO-03：停止后若系统声音有有效 buffer，记录独立 CAF 并可在详情页播放；无 buffer 时明确显示“未检测到系统声音”，不伪装为双轨成功。
- AC-AUDIO-04：自动测试覆盖 ScreenCaptureKit 启停、无权限/无显示器映射和双轨文件元数据；真实 Mac Journey 需在播放视频或会议声音时人工确认 CAF 可听见。

## 非目标

- 不默认打开屏幕录制权限，不静默录制系统声音。
- 不承诺捕获 DRM/受保护媒体，也不把系统声音与麦克风强制混音。
- 不把参考截图的黑色主题直接复制到 Woice；Woice 继续使用原生 macOS 材质、字体和语义色。
