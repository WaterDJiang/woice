# 系统声音来源与采集事实可见性

## 结论

Woice 当前不是用麦克风“录”电脑声音，而是通过 ScreenCaptureKit“获取”系统输出，再将其保存为同一录音 ID 下的独立 CAF 音轨。麦克风 WAV 与系统 CAF 不混音；当前 ASR 默认仍读取麦克风 WAV。

当前 Mac 的真实历史已证明底层采集成功：最近录音存在有效 CAF，时长约 29–31 秒，音量峰值为非静音值。用户感知为“没有录到”，主要原因是系统声音轨道位置不醒目，且停止后的页面没有显示“已获取系统输出”的可验证事实。

## 目标

- 在设置中把“录制电脑播放的声音”与权限、能力检查和失败说明放在同一个任务区。
- 录音详情优先展示独立系统声音轨道，明确它不是麦克风 WAV，也不是当前原文的默认转写来源。
- 停止后以 CAF 文件、时长、buffer 和峰值显示采集事实；无有效信号时说明“已启动但没有可听见的系统输出”。
- 保留原始双轨，不强制混音、不覆盖麦克风录音；系统声音转写作为后续独立能力，不在本次隐式改变。

## 验收标准

- AC-OBS-01：用户能在设置同一区块看到开关、屏幕录制权限、系统能力和重新检查动作。
- AC-OBS-02：录音中同时显示麦克风状态与系统声音状态；系统声音只显示“已开始”不能伪装“已有声音”。
- AC-OBS-03：有效系统声音停止后，详情页在麦克风播放器附近显示“电脑播放的声音（独立音轨）”，并显示可复听时长和有效信号状态。
- AC-OBS-04：系统声音 CAF 缺失、无 buffer 或峰值为零时，显示可执行诊断，麦克风 WAV 仍保留。
- AC-OBS-05：旧 RecordingRecord JSON/SQLite payload 缺少新增字段时仍可读取。
- AC-OBS-06：真实 Mac 播放系统声音样本时，CAF 可读取、时长大于零、峰值大于零；`make verify` 通过。

## 边界

- ScreenCaptureKit 的权限名称是 macOS“屏幕录制”，不是“麦克风”或钥匙串权限。
- DRM/受保护媒体、无可共享显示器、静音输出设备和远程桌面不保证有有效系统信号。
- 当前版本不会把系统 CAF 自动合并到默认 ASR；用户需要在详情页播放系统声音轨道确认采集结果。
