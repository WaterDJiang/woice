# Woice 双版本分发与模型接入规格

> 状态：实现中；本机 ASR、模型版本选择、bundled/downloaded 库存与 Core/Offline ad hoc 打包已先行，正式发行门禁尚未完成  
> 日期：2026-08-22  
> 关联：[产品需求初稿](2026-08-22-product-research-and-design-draft.md) · [M2 Provider SDK](2026-08-22-m2-provider-sdk.md) · [当前开发计划](../plan/2026-08-22-m0-mvp.md)

> 定位关系：本规格继续有效，负责把录音转成可使用文字的核心能力；通用摘要、规划、编码等后续操作由[语音上下文与 Agent 协作](2026-08-22-voice-context-source-positioning.md)承接。

## 1. 结论

Woice 使用同一代码、同一 Bundle ID、同一数据目录和同一配置 Schema 产出两个下载包：

| 下载包 | 面向用户 | 随包内容 | 首次转录 |
|---|---|---|---|
| Woice 轻量版（Core） | 已有本地 ASR 服务、希望控制下载体积的用户 | App、系统朗读与 ASR 模型管理能力；不含第三方模型权重 | 连接已有 ASR、主动下载推荐模型，或先只保存录音 |
| Woice 离线版（Offline） | 希望下载后断网开箱即用的多数用户 | 与轻量版相同的 App，加一个经过验证的默认 ASR 模型包 | 麦克风授权后即可在本机完成录音与最终转录 |

两版不是两个产品分支。`Offline` 只比 `Core` 多一个已安装模型来源；业务能力、更新通道、历史数据和用户可接入的 Provider 完全一致。

推荐发布页默认突出“离线版”，把“轻量版”标为适合已有本地 AI 环境的高级选择。App 内仍统一显示产品名 `Woice`，不在功能名称中制造版本差异。

## 2. 默认模型决策

### 2.1 首发候选

- 默认 ASR 候选：WhisperKit 的 `large-v3-v20240930_626MB` Core ML 模型。
- 系统朗读：继续使用 macOS `AVSpeechSynthesizer`，不进入模型下载和路由范围。
- 通用 LLM：不属于 M2-08 核心；录音后的处理交给 M2-09 外部 Agent，现有 LLM Endpoint 仅保留兼容。

WhisperKit 默认模型只有在 M1 16 GB、macOS 14 的固定样本基准满足以下门槛后才能冻结：

- 5 分钟中英文混合样本 RTF 不高于 1.0。
- 峰值内存不超过 4 GB。
- 模型包完整性、来源、许可证和 Notice 可自动验证。
- 断网、首次加载、重复加载和损坏模型均有确定性结果。

不满足时按顺序降级评估 Whisper `turbo`、`small`；不得放宽性能门槛或隐式改用云端。

### 2.2 后续 ASR 对照组

- ASR 中文增强候选：SenseVoiceSmall INT8、Qwen3-ASR-0.6B。
- 非 MIT 权重或依赖必须先形成 ADR；候选不等于允许随包分发。

## 3. 用户目标

- 下载离线版后无需理解 Endpoint、模型 ID 或运行时即可完成首次转录。
- 下载轻量版后能在三步内发现并连接已有本地服务，不必手抄复杂 URL。
- 没有模型时仍能录音、复听和保存；界面明确显示“等待选择模型”，不伪装成处理中。
- 用户可随时更换 ASR；历史转写任务保留当时的 Provider、模型和配置快照。
- 转写完成的素材可以由 M2-09 发送给外部 Agent，不要求 M2-08 内置 LLM。
- 本机、局域网、云端三种数据去向始终可见；本地失败不自动转云端。
- 用户从轻量版安装推荐模型后，获得与离线版完全相同的运行能力。

## 4. 支持边界

### 4.1 首版必须支持

- 随 App 签名的内置 Swift Provider。
- Woice 推荐模型包的发现、校验、安装、选择、删除和状态展示。
- OpenAI-compatible ASR：`POST /v1/audio/transcriptions`。
- 可选 `GET /v1/models` 模型发现；服务不支持时允许手动填写模型 ID。
- 现有受控进程 Provider Manifest/Runner；外部 Provider 仍需签名、来源和权限检查。
- 本机 ASR 预设：通用 OpenAI-compatible、whisper.cpp server、faster-whisper server、FunASR/LocalAI。

### 4.2 首版不承诺

- 不承诺把任意 GGUF、ONNX、Core ML、PyTorch 文件拖入 Woice 就能运行。
- 不扫描所有本机端口，不在后台自动发现服务。
- 不下载或加载任意动态库、Swift bundle。
- 不自动安装 Python、Node、Homebrew、Docker 或第三方模型运行时。
- 不因为用户选择了“自动”就把本地失败请求发送到云端。
- 不在两个发行包之间维护不同数据库 Schema、Feature Flag 或业务逻辑。

## 5. 首次启动需求

### 5.1 离线版

首次启动第三步显示：

- “本机转录模型已包含”。
- 模型名称、约 626 MB 体积、处理位置“这台 Mac”、语言范围和许可证入口。
- `测试模型` 与 `稍后测试`；不要求用户填写任何表单。

麦克风授权成功后，用户可直接录制 3 秒测试语音。测试结果不进入历史；成功后显示首载耗时和“已可离线使用”。

### 5.2 轻量版

首次启动第三步标题为“选择转录方式”，提供三个主选项：

1. `查找这台 Mac 上的服务`：用户点击后才探测允许列表中的 loopback 地址。
2. `下载推荐模型`：显示体积、磁盘空间、许可证和数据位置，确认后开始可恢复下载。
3. `先只保存录音`：立即进入产品；停止录音后显示“录音已安全保存，等待选择模型”。

`手动连接`作为次级入口；云端服务放在手动连接流程，不与本地推荐并列抢占主视觉。

## 6. ASR 模型与服务连接向导

向导最多三个主步骤：

### 步骤一：选择运行位置

- 这台 Mac：内置模型、localhost 服务、受控进程。
- 局域网设备：用户明确输入或选择已知地址。
- 云端服务：显示目标域名、数据类型和首次外发授权。

### 步骤二：选择服务和模型

- 已发现服务显示名称、能力、地址、版本和状态。
- 支持 `/v1/models` 时用选择器，不要求手填模型 ID。
- 无法列举模型时显示一个模型字段和预设示例。
- API Key 字段只在服务声明需要时出现，继续复用 Keychain。
- 高级参数折叠，默认只展示位置、服务、模型三个决定。

### 步骤三：测试并启用

- ASR 使用 Woice 生成的短测试 WAV，不发送历史录音。
- 成功结果显示首包/总延迟、返回能力、实际数据位置和“设为默认”。
- 失败结果必须包含：发生什么、录音是否安全、修改配置/重试/查看诊断三个动作中的适用项。

## 7. 设置页需求

现有“服务”页面改名为“模型与转写”，先展示 ASR 状态，不再先展示原始 Endpoint 表单；Agent 连接进入独立的“Agent 与连接”：

| 区块 | 默认信息 | 主动作 |
|---|---|---|
| 语言转文字 | 当前 Provider、模型、位置、健康、时间戳/流式能力 | 更换、测试 |
| 已安装 ASR 模型 | 模型大小、版本、来源、许可证、磁盘占用 | 更新、删除 |
| 高级 ASR 连接 | Endpoint、模型 ID、Keychain、进程 Provider | 编辑、导入 Manifest |

Popover 只显示当前 Profile 的处理位置和可执行错误入口，不放模型列表或下载管理。

## 8. 状态与错误语义

Provider/模型健康状态至少区分：

- 未配置。
- 等待选择模型。
- 下载中/校验中。
- 已就绪。
- 需要授权。
- 模型缺失。
- 服务不可达。
- 能力不兼容。
- 来源不可信。
- 已停用。

处理任务在没有可用 Provider 时进入“等待选择模型”，不是 `running` 或成功。配置本机 Provider 后，Woice 询问是否处理现有待转录录音；云端 Provider 仍逐目标执行外发授权。

## 9. 数据去向策略

每个 Provider 配置必须声明并由运行时校验 `onDevice`、`localNetwork` 或 `cloud`：

- 进程内、Unix Socket、`127.0.0.1`、`::1`：这台 Mac。
- 私网地址或用户指定局域网主机：局域网设备。
- 公网主机：云端。
- 无法判定：显示“位置待确认”，禁止自动启用。

本机服务不需要每条录音弹出云端外发确认，但首次连接时说明它是独立进程；局域网和云端必须显示目标和数据类型。配置快照随 Job 保存，运行中的任务不因默认 Provider 被切换而改路由。

## 10. 分发与升级需求

- 两个 DMG 使用同一 `CFBundleIdentifier`、Short Version、Build Version 和数据库目录。
- 文件名：`Woice-Core-{version}.dmg`、`Woice-Offline-{version}.dmg`。
- 离线版模型放在签名 App 的只读 Resources；不得在首次启动时复制一份造成双倍占用。
- 用户下载模型放在 Application Support 的版本目录，使用临时文件、逐文件 SHA-256、签名清单和原子切换。
- Core 覆盖安装 Offline、Offline 覆盖安装 Core、版本升级均不得删除用户模型、录音、配置或 Keychain。
- Offline 被 Core 覆盖后，如当前默认只存在于旧 App Resources，应明确提示模型暂不可用并提供重新下载；不得静默换云端。
- 两个发行包分别签名、公证和做干净安装、覆盖安装、断网启动验收。

## 11. 安全与许可证

- 模型包只包含权重、Tokenizer、配置和许可证，不包含任意可执行代码。
- 下载目录不可执行；Provider 可执行文件继续走现有受控进程信任验证。
- 模型清单记录来源 URL、版本、SPDX/自定义许可证、版权、文件哈希、支持架构和最低系统。
- API Key 不进入模型清单、SQLite、日志或进程环境。
- 模型下载必须由用户动作触发，显示大小和来源；失败不自动换镜像。
- Voice cloning Provider 后续接入时必须另立同意、来源音频和防冒用规格，不随普通 TTS 接入默认开启。

## 12. 验收标准

- AC-MI-001：两个发行包除模型资源和发行清单外，应用二进制与功能一致。
- AC-MI-002：离线版在断网的干净 Mac 上完成“录音 -> 本机 ASR -> 原始转录”，无外部请求。
- AC-MI-003：轻量版没有模型时仍可录音/复听，界面不显示虚假处理成功。
- AC-MI-004：轻量版一键安装推荐模型后，与离线版使用同一 Provider ID、模型 ID 和 Pipeline。
- AC-MI-005：用户主动扫描后可发现至少两个固定 loopback Fixture；未点击前不扫描。
- AC-MI-006：支持 `/v1/models` 的服务无需手填模型 ID；不支持时可手动完成连接。
- AC-MI-007：切换本机/局域网/云端时，处理位置、授权策略和历史配置快照正确。
- AC-MI-008：损坏、签名不符、空间不足、中断下载均不产生“已安装”事实；旧可用版本不受影响。
- AC-MI-009：Core/Offline 双向覆盖安装保留历史、设置、Keychain 和用户下载模型。
- AC-MI-010：模型和代码依赖均进入 Notices/SBOM；未批准的非 MIT 项不得随包分发。
- AC-MI-011：VoiceOver、键盘导航、深浅色、高对比和 Reduce Motion 覆盖连接向导与下载状态。
- AC-MI-012：两名首次用户在不看说明的情况下，3 秒内能说清“当前有没有模型、在哪里处理、下一步做什么”。

## 13. 产品指标

- 离线版首次成功转录完成率不低于 90%。
- 轻量版“发现本地服务或开始推荐模型下载”完成率不低于 80%。
- 已发现服务的连接流程不超过三个主步骤。
- Provider/模型相关失败中，100% 保留原始录音并提供下一步动作。
- Core DMG 目标不超过 150 MB；Offline DMG 目标不超过 1 GB，最终以签名公证产物实测为准。
