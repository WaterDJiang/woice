# 全局按钮反馈与操作质感规格

## 目标

让 Woice 的按钮在用户点击后立即表达“已按下、正在处理、已完成或失败”，尤其是“复制原文”“粘贴到当前应用”“刷新”等容易产生无声操作的动作。

## 范围

- 建立统一的操作反馈模型和轻量反馈提示，不引入网页式 Toast 堆叠。
- 可见操作补齐按下态、处理中禁用态、成功确认和失败恢复路径。
- 复制、粘贴、刷新、测试输入、权限检查、导出、模型切换/导入和设置保存使用一致语义。
- VoiceOver 同步播报结果；颜色不作为唯一状态信号。

## 交互原则

- 100 ms 内出现按下态；异步操作超过 300 ms 显示 ProgressView，并暂时禁用重复点击。
- 成功反馈使用 `checkmark.circle.fill + 文案`，保留约 2 秒；失败使用 `exclamationmark.triangle.fill + 原因 + 可恢复动作`。
- 轻量动作优先在原按钮内变为“已复制/已粘贴/已刷新”；跨区域或异步任务同时在工作台/Popover 顶部显示一条非阻塞状态提示。
- 不用弹窗确认普通成功动作，不遮挡录音状态，不自动滚动用户当前内容。
- 操作失败不能清除原始录音、原文或已有设置；重复点击必须幂等或被禁用。

## 状态契约

| 状态 | 视觉 | 文案 | VoiceOver |
|---|---|---|---|
| idle | 原按钮 | 原动作 | 动作名称 |
| pressed | 原生按钮按下态 | 不变 | 不重复播报 |
| working | Spinner + 禁用 | 处理中… | “正在…” |
| success | 勾选图标 + 成功文案 | 已复制/已粘贴/已刷新 | “已…” |
| failure | 警告图标 + 原因 | 失败原因与下一步 | “失败：…” |

## 验收标准

- 复制原文后按钮能看到“已复制”，粘贴成功后能看到“已粘贴”；无原文或权限失败显示可读原因。
- 麦克风刷新、辅助功能重新检查、系统音频重新检查后显示“已刷新/已检查”，执行中不能重复点击。
- 测试输入、测试转写 API、模型下载/切换/导入、设置保存在执行期间显示处理中，完成或失败有结果。
- 所有新增反馈支持浅色、深色、高对比度、键盘和 VoiceOver；减少动态效果时不依赖动画表达状态。
- `make docs-check`、`make harness-check`、`make lint`、`make test` 和 `make verify` 通过。

## 边界

- 保留系统 `Button`、`ProgressView`、语义色和 SF Symbols，不创建全局网页 Toast 或自定义弹窗体系。
- 不改变录音、转写、权限和存储业务逻辑；只补充可观察反馈与重复点击保护。
