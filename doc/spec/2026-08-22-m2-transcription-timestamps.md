# M2-03b 转写时间戳片段基础

> 状态：基础实现完成，待真实第三方服务验收  

> 创建日期：2026-08-22  
> 关联计划：[`2026-08-22-m0-mvp.md`](../plan/2026-08-22-m0-mvp.md)

## 1. 目标

在不破坏现有纯文本转写 API 的前提下，为用户可选地请求 OpenAI-compatible `verbose_json`，保存并展示 ASR 返回的时间戳片段，作为会议摘要、待办和时间戳复听的稳定输入。

## 2. 范围

- 设置页增加“保留转写时间戳”开关，默认关闭。
- 开关开启时，multipart 请求增加 `response_format=verbose_json`。
- 解析 `text` 与可选 `segments[{start,end,text}]`；服务只返回纯文本时仍保存原文，不伪造时间戳。
- 原始转录文本保持不可覆盖；时间戳片段作为同一转写版本的附加元数据保存。
- 详情页在原文下显示可选时间戳片段；点击片段可把原始 WAV 播放位置跳到对应起点。

## 3. 不在本工作包

- 不要求所有自定义 Provider 支持 verbose_json。
- 不把片段自动当作说话人、置信度或事实判断。
- 不实现实时增量 ASR、说话人分离或自动会议摘要策略。

## 4. 验收标准

- 默认关闭时，现有 multipart 请求字段和纯文本响应行为不变。
- 开启时请求包含 `response_format=verbose_json`，正确解析时间戳片段。
- 缺少 `segments`、返回纯文本或片段格式异常时，原文仍可保存，错误边界可诊断。
- 旧历史 JSON 缺少片段字段时可读取；新增片段不会覆盖原始文本。
- 时间戳片段缺少对应原始音频时只禁用跳转，不删除转录文本。
- `make verify` 通过，详情页编译并显示时间戳片段。
