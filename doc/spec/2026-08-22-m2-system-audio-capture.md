# M2-01 系统音频双轨落盘

> 状态：实现完成，待真实 App UI 验收  
> 创建日期：2026-08-22  
> 前置规格：[系统音频能力探针](2026-08-22-m2-system-audio-dual-track.md)

## 1. 目标

在用户显式开启会议模式后，使用 ScreenCaptureKit 捕获系统音频，并与 AVAudioEngine 麦克风轨道分别保存到本机。两条原始轨道可独立复听；任一轨道失败时保留另一条并给出明确状态。

## 2. 范围

- 能力查询优先使用当前屏幕目标；若当前屏幕目标为空，再用非仅屏幕目标查询一次，并继续要求用户主动开启会议录音。
- `SCStream` 只订阅 `.audio` sample buffer，不录制屏幕画面。
- 系统音频使用 CAF 文件保存，麦克风继续使用 WAV；两者使用同一录音会话 ID。
- 记录系统音频文件名、采样率、声道和实际帧数，时长以已写入帧为准。
- 停止采集时显式收尾 CAF 写入句柄，再允许历史、复听或导出读取系统音频文件。
- 会议模式必须由用户在设置中开启；未开启时不请求屏幕录制权限、不创建系统音频文件。
- 设置和详情页显示双轨文件状态，并提供系统音频复听。
- 录音中的状态卡明确显示系统声音轨道是否已开始；系统轨道失败不能伪装成双轨成功。

## 3. 不在本工作包

- 屏幕画面、摄像头、说话人分离和实时转写。
- 自动开始会议录音、静默权限请求或云端备份。
- 把系统音频和麦克风混成一个不可追溯的文件。

## 4. 验收标准

- 未开启会议模式时，现有麦克风录音行为和文件格式不变。
- 开启会议模式且权限已授权时，录音结束后至少生成麦克风 WAV；若系统音频收到帧，则生成 CAF 并在历史详情可播放。
- 系统音频启动或写入失败时，麦克风 WAV 仍保留，记录页明确说明失败原因。
- 开启会议模式录音时，Popover 同时显示“系统声音采集已开启”或“系统声音未开始”，并说明麦克风仍会继续录音。
- 停止录音后，双轨时长均来自实际写入帧，不使用按钮点击时间替代文件事实。
- `make verify` 通过；新增样本测试覆盖旧 JSON 解码、系统音频文件状态和音频 sample buffer 写入契约。
- 真实 Mac 完成一次“开启会议模式 -> 播放系统声音 -> 录音 -> 停止 -> 复听”验证；未完成前不得标记 M2-01 完成。

## 5. 影响面

- `AppSettings` 新增兼容旧配置的会议模式开关。
- `RecordingRecord` 新增可选系统音频文件引用，旧历史 JSON 无需迁移即可读取。
- 新增 `SystemAudioCaptureService`，不让 UI 直接操作 ScreenCaptureKit 或文件。
- `WorkspaceStore`、历史详情和删除流程同时管理两条原始轨道。
