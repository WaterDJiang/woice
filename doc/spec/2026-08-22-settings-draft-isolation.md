# 设置页草稿隔离

## 目标

让设置窗口遵循 macOS 常见的草稿语义：用户编辑期间只改变当前窗口草稿；点击“保存设置”成功后才提交到 AppState、Keychain 和本地配置。关闭或“还原”不得留下半成品配置。提交时按字段差异写入，普通设置不应因为 API Key 未修改而访问 Keychain。

## 范围

- 录音、服务、文件与隐私三组设置共用一个草稿快照。
- 底部状态栏明确显示“未保存更改”、保存失败或已保存。
- 保存失败时不把草稿当成已提交设置，也不重新注册快捷键。
- “还原”恢复最近一次成功保存的快照。
- 只有 API Key 字段发生变化时才读写对应的 Keychain 项；只修改录音、系统音频、快捷键、Endpoint、模型或文件设置时不触发 Keychain 访问。
- ASR 与 LLM API Key 分别保存；只修改其中一个时不读写另一个 Keychain 项。
- 不改变 API Key 的 Keychain 存储、外发确认或录音文件。

## 验收标准

- 编辑 Endpoint、模型、录音开关或快捷键后，`AppState.settings` 在保存前保持原值。
- 点击“还原”后草稿与最近一次成功保存的值一致，保存按钮禁用。
- 保存成功后草稿、AppState 和持久化设置一致，快捷键按新配置注册。
- Endpoint/模型校验失败时保存返回失败，页面保留可修正草稿并显示错误，不显示“已保存”。
- 只修改普通设置时，保存成功且 Keychain 读写计数为零；修改 ASR/LLM Key 时只写入对应账号。
- `make verify` 及现有真实麦克风/ASR 验收不回归。

## 影响面

- `SettingsView`：使用独立草稿快照并将三组 Pane 改为绑定草稿。
- `AppState.saveSettings`：接受候选快照，按字段差异分别提交 Keychain 和本地配置；只有对应 API Key 变更时才访问对应 Keychain 项，全部成功后才提交内存状态。
- 文档：记录草稿与已提交设置的边界。
