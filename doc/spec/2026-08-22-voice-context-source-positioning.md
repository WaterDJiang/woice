# Woice 语音上下文来源产品定位

> 状态：已确认的产品方向  
> 日期：2026-08-22  
> 关联：[产品需求初稿](2026-08-22-product-research-and-design-draft.md) · [双版本与模型接入](2026-08-22-dual-edition-model-integration.md)

> 再次确认：本文件是当前需求的唯一定位基线。最新修正不是“做一个更好的 AI 网关”，而是“把录音场景做透，并成为其他 Agent 可调用的语音上下文来源”。

## 1. 产品定义

Woice 不是 AI 网关、AI 工具入口、聊天聚合器或通用 Agent 控制台。Woice 首先是把录音场景做透的 macOS 工具：可靠采集声音，把声音转成文字，并把音频、原始转录、时间戳和派生结果沉淀为可搜索、可复听、可引用的上下文素材。

在素材完成之后，Woice 可以把用户选择的素材交给某个已验证、已授权的外部 AI Agent/CLI 继续处理；外部 Agent 也可以在授权范围内查询和读取 Woice 素材。Woice 不负责替代这些 Agent 的推理、规划、编码或内容生产能力，也不承诺一次接入或自动兼容“所有 AI CLI”。

一句话定位：

> Woice 是面向个人与 AI Agent 的语音素材采集器和上下文来源。

### 1.2 本次需求修正版（优先级裁决）

以下解释覆盖此前任何“AI 工具入口”“统一网关”或“先接 Agent 再完善录音”的表述：

| 优先级 | 需求 | 说明 |
|---|---|---|
| P0 核心能力 | 录音、原始音频可靠保存、转写、模型管理、复听、搜索、复制和导出 | 没有 Agent 时也必须独立完成；Core/Offline 与本机模型下载属于这一层 |
| P1 素材使用 | 基于已经提交的音频/转录/时间戳素材完成派发或读取 | Woice 只负责选择、授权、打包、传输、状态、结果归档和审计 |
| P1 外部推理 | 外部 Agent/CLI 负责理解、推理、规划、编码、联网和业务动作 | Woice 不在自身内部实现通用 AI 能力或 Agent Loop |
| 独立边界 | Woice 出站调用 Agent 与 Agent 入站读取 Woice 是两种独立接口 | 二者不能合并成 Agent 网关、统一入口或聊天聚合器 |

因此，“Woice 可以调用其他 AI Agent 的 CLI/能力”只表示**素材完成后的可选交付动作**；“Codex、小龙虾等 Agent 可以调用 Woice”只表示**经过授权的语音上下文读取**。这两句话都不能改变 Woice 首先是录音与转写产品的定位。

### 1.1 产品合同

Woice 对用户承诺的第一件事只有一件：用户说过的话能够被可靠录下、保存、转成文字，并在之后被自己或授权的外部工具找到和使用。

- 核心闭环：`录音 -> 原始音频落盘 -> 本机/已授权 ASR -> 原始转录 -> 复听/搜索/导出`。
- 可选协作：素材完成后，用户可以把选中的 Artifact 交给某个已验证的外部 Agent/CLI；Agent 也可以在授权范围内读取 Artifact。
- 依赖关系：核心闭环不依赖任何 Agent；Agent 协作失败不能让录音、转写、复听、搜索或导出失败。
- 产品表达：主界面和首启先表达“录音、转写、素材”，不表达“接入多少 Agent”。
- 兼容承诺：只承诺已经完成真实验收的适配器和通用协议边界，不承诺“所有 AI CLI”。

因此，“调用外部 Agent”不是 Woice 的产品入口，而是素材完成后的一个出口；“被 Agent 调用”不是开放数据库，而是经过权限、范围、分页和审计控制的上下文来源接口。

本次需求修正的核心判断：

- 录音、原始音频保存、转写、模型管理、复听、搜索和导出是 Woice 的产品价值，不是给 Agent 准备的临时前置步骤。
- Core/Offline 双版本、本机模型下载与断网转写继续保留，并且属于核心发布门槛。
- Agent 连接只在素材已经安全保存、可读取、可追溯之后出现；没有任何 Agent 时，Woice 仍必须完成完整基础闭环。
- “Woice 调用外部 Agent”与“外部 Agent 调用 Woice”都是边界协作能力，不改变 Woice 的核心身份。

## 2. 能力分层

### 2.1 第一层：素材收集，属于产品核心

- 麦克风录音、系统音频录制和双音轨。
- 清晰可见的录音状态、时长、电平、VAD 和错误。
- 原始音频可靠落盘、崩溃恢复和不可覆盖。
- 复听、时间戳定位、分段和历史管理。
- 快捷键、菜单栏、设置、权限和存储管理。

没有可靠音频，就没有后续上下文；该层优先级最高。

### 2.2 第二层：素材结构化，属于产品核心

- 把录音转成原始文字，保留时间戳、语言和处理来源。
- 支持本机模型、用户下载模型和 OpenAI-compatible ASR。
- 保留 Woice Core/Offline 双版本与模型下载计划。
- 无模型或转写失败时仍保存、复听录音，并允许以后补转写。
- 原始转录不可覆盖；重转录生成新的 Artifact。
- 搜索、复制、Markdown 导出和上下文引用。

ASR 是把音频变成可使用素材的必要基础能力，不等同于 Woice 自己成为 AI Agent。

### 2.3 第三层：素材运用，优先交给外部 Agent

- 用户从录音详情或素材列表选择音频、原文、时间戳片段或 Markdown。
- 用户选择一个已安装、已验证并明确授权的目标 Agent/CLI 和任务，例如“整理成周报”“生成开发任务”“提取客户异议”。
- Woice 负责打包上下文、展示数据去向、派发任务、跟踪状态和接收结果。
- 外部 Agent 负责理解、推理、规划、编码、联网和业务动作。
- 返回结果保存为新的派生 Artifact，并关联原始素材、目标 Agent、时间和任务说明。
- 返回内容默认只展示和保存，不自动执行命令、不自动覆盖原始素材。

这里的“调用”是一次明确的素材交付，不是把 Woice 变成 Agent 入口。首版只承诺通用协议边界和实际完成验收的适配器；新增 Agent 按需求逐个验证，不建设任意 CLI 的自动发现、统一编排或聚合入口。

Woice 可以保留少量确定性的展示转换，例如 Markdown 解析；不新增自有 Prompt 编排、Agent 循环或通用 LLM 工作流引擎。

### 2.4 第四层：Woice 作为 Agent 的上下文工具

- Codex、PI、“小龙虾”等 Agent 可以通过 MCP、专用扩展或本地 RPC 查询 Woice。
- 默认提供状态、素材列表、搜索、录音详情、转录和 Artifact 分页读取。
- Agent 默认不能静默启动麦克风；开始录音仍需要用户动作或单独开启的明确权限。
- 每次读取和派发记录调用方、素材、用途、时间和结果。

该层服务于“语音上下文来源”，不把 Woice 变成 Agent 控制台。

## 3. 产品主流程

```text
录音
  -> 原始音频安全落盘
  -> 本机/外部 ASR 转成原始文字
  -> 复听、搜索、选择上下文
  -> 交给外部 Agent 继续处理
  -> 接收并保存派生结果
```

外部 Agent 使用 Woice 的流程：

```text
Agent 发起查询
  -> Woice 权限与范围检查
  -> 返回音频/转录/片段的引用或分页内容
  -> Agent 在自己的运行时完成后续任务
```

## 4. 核心用户场景

### 场景 A：快速口述成为工作上下文

用户录制想法，Woice 保存并转写。用户可以直接复制，也可以把这条素材发送给 Codex，让 Codex 基于原文生成实施计划。

### 场景 B：会议素材交给外部 Agent

Woice 保存麦克风与系统音频、时间戳和原始转录。用户选择相关片段发送给外部 Agent，由 Agent 生成纪要、待办、邮件或项目任务；Woice 只保存返回结果及来源关系。

### 场景 C：Agent 主动取得语音上下文

用户在 Codex 中要求“读取我今天关于 Woice 的最后一段录音”。Codex 通过 Woice 工具搜索并读取授权范围内的转录，不直接访问 SQLite、Keychain 或录音设备。

### 场景 D：没有 Agent 也能完成基础工作

用户未安装任何 Agent 时，仍能录音、转写、复听、搜索、复制和导出。Agent 不是完成核心录音闭环的前置条件。

## 5. 产品边界

### Woice 必须负责

- 音频采集、文件完整性、时长真相和权限。
- 本机或可配置 ASR，包含模型下载与双版本体验。
- Artifact、Transcript、Job、来源关系和恢复。
- 素材搜索、选择、复听、导出和上下文打包。
- Agent 连接、派发、状态、结果收集和审计。
- 外发确认、路径权限、输出上限和失败恢复。

### Woice 不负责

- 自研基础模型。
- 通用 Agent 的推理、规划、编码和工具循环。
- 在 Woice 内复制 Codex、Claude Code 或其他 Agent 的完整交互界面。
- 自动决定应该把素材交给哪个 Agent。
- 自动发现、自动安装或自动兼容所有 AI CLI。
- 自动执行 Agent 返回的脚本、命令、补丁或外部发布动作。
- 把本地失败静默切到云端或另一个 Agent。

## 6. Agent/CLI 兼容定义

“可调用其他 AI CLI”不等于执行任意 Shell 字符串。首版采用两层兼容：

- 通用协议：MCP、版本化本地 RPC、受控 stdin/stdout JSON。
- 专用适配：对 Codex CLI、PI 等高频产品提供锁定版本的薄适配。

只有满足以下条件的 CLI 才能作为可用目标：

- 可确定可执行文件、版本和输入输出协议。
- 支持非交互或可解释的等待审批状态。
- 可以限定工作目录、环境变量、超时和输出大小。
- 凭据由目标 CLI 自己管理，Woice 不读取或复制。

“小龙虾”等产品优先通过 MCP 或通用 CLI 契约接入；取得其准确命令、版本和协议后再增加专用适配，不在核心代码里写产品特例。

## 7. 功能需求增量

- FR-AG-001：用户可以从单条录音、选中片段或多条素材创建外部处理任务。
- FR-AG-002：任务必须保存目标 Agent、指令、输入 Artifact 引用、工作目录权限和数据位置快照。
- FR-AG-003：Woice 不改写用户指令，不使用内置 LLM 补充或重新规划任务。
- FR-AG-004：外部进程必须通过受控参数模板启动，不接受调用方提供任意命令行。
- FR-AG-005：任务状态至少包含等待确认、排队、运行、等待 Agent 审批、完成、失败、取消和中断。
- FR-AG-006：文本、Markdown、JSON 和文件引用结果保存为派生 Artifact；标准输出日志不是用户结果。
- FR-AG-007：Agent 读取 Woice 素材时使用分页与显式范围，不直接读取数据库或 Application Support。
- FR-AG-008：Agent 发起录音默认返回 `USER_GESTURE_REQUIRED`。
- FR-AG-009：外部 Agent 的凭据、登录态和配置由其自身管理，Woice 只保存连接状态和非敏感版本信息。
- FR-AG-010：Agent 未安装、未登录或处理失败不影响录音、转写、复听和导出。
- FR-AG-011：所有 Agent 调用记录调用方、目标、输入 Artifact、权限、状态和时间。
- FR-AG-012：Agent 返回内容不得自动覆盖原始音频、原始转录或已存在 Artifact。

## 8. UX 原则

- 主界面先回答“有没有录到、有没有转成文字、素材在哪里”。
- Agent 动作出现在素材完成之后，文案为“发送给…”或“用…处理”，不使用“进入 AI 网关”。
- 用户派发前看到目标 Agent、将发送的内容、工作目录和是否联网。
- 处理中显示目标 Agent 和阶段；失败说明素材仍安全，并提供重试、更换目标或仅保留素材。
- 设置页使用“Agent 与连接”，不使用“AI 中心”或“模型市场”作为产品主导航。
- 没有配置 Agent 时不制造错误状态，也不影响首次录音引导。
- 首次启动和主界面首先讲清“录音、转写、素材”，不先展示 Agent、CLI 或连接器。
- “发送给…”是素材完成后的次级动作；不能成为录音按钮、转写状态或历史列表的替代入口。

## 9. 验收标准

- AC-VC-001：未安装 Agent 时，Woice 仍完成录音、转写、复听、搜索和导出。
- AC-VC-002：Core/Offline 两版的模型接入、下载和断网转写计划保持有效。
- AC-VC-003：用户可在录音详情中选择一个 Artifact 和目标 Agent，三步内创建处理任务。
- AC-VC-004：任务失败、CLI 崩溃或输出超限时，原始音频和原始转录 SHA-256 不变。
- AC-VC-005：至少两个真实 CLI 适配完成派发、状态跟踪和结果 Artifact 回收。
- AC-VC-006：至少两个外部 Agent 通过 MCP/RPC 完成素材搜索与分页读取。
- AC-VC-007：Agent 默认无法静默开始录音，也不能读取未授权目录或 Keychain。
- AC-VC-008：Woice 不包含通用 LLM Agent 循环；后续内容处理由目标 Agent 完成。
- AC-VC-009：两名首次用户在 3 秒内能回答“Woice 首先用来做什么”，答案必须首先包含录音或语音素材，而不是 Agent 网关。
- AC-VC-010：在未安装、未登录或全部外部 Agent 不可用时，Woice 仍可完成录音、转写、复听、搜索和导出；不能把 Agent 故障显示成核心能力故障。
- AC-VC-011：产品兼容声明只列出已验证的 Agent/CLI 适配器与协议，不使用“支持所有 AI CLI”“统一接入所有 Agent”等表述。

- M2-08 双版本、WhisperKit、模型下载和本机转写计划继续执行。
- 当前 OpenAI-compatible ASR 继续作为素材结构化能力。
- 当前 LLM Markdown 能力保留兼容，但不继续扩展为 Woice 自有 AI 工作流；后续迁为外部 Agent 处理路径。
- PI、本地 RPC、Provider Runner 可复用为 Agent 接入基础。
- 新增 M2-09“语音素材到 Agent 的上下文协作”，不得阻塞 M2-08 和录音质量门禁。
- 旧 M3 DeepSeek Harness/插件生态阶段已停止；准确契约确认后的单一产品适配只能进入 M2-09 P1，不能恢复旧 M3。

## 11. 再次修正后的排期裁决

- **R0/R1/R2 是产品核心发布线**：录音可靠性、ASR/模型、Core/Offline、复听、搜索、导出和 Artifact 来源链必须先完成。
- **M2-09 是核心完成后的协作扩展线**：可以在核心发布后继续迭代，不得反向阻塞核心版本。
- **Agent 出站和入站都按“素材接口”实现**：出站是选中的 Artifact 交付，入站是授权的 Artifact 查询；它们不共享“统一 Agent 网关”抽象。
- **删除 Agent 层仍应可发布**：移除所有 Connector/CLI 后，Woice 仍应被用户独立使用，并通过核心验收。
- **不做能力总入口**：不提供 Agent 列表首页、聊天聚合、自动选 Agent、跨 Agent 编排、任意 CLI 执行或统一会话历史。
