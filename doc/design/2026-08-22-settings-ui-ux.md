# Woice 设置页 UI/UX 设计决策

> 状态：已实施，待解锁桌面进行人工 Journey

> 产品定位更新：本文件记录当前已实现设置页。M2-08 将“服务”收敛为“模型与转写”，M2-09 再新增独立“Agent 与连接”；Agent 设置不得替代录音和 ASR 的主信息层级。

## 设计目标

- 使用 macOS 原生 Settings 语义，不做网页式仪表盘。
- 让用户在 3 秒内回答：麦克风是否可用、服务是否已配置、改动是否已保存。
- 把底层权限/Provider 错误翻译成下一步动作，不隐藏数据安全边界。
- 录音、服务、文件与隐私分组互斥，避免同一设置出现两个入口。

## 页面结构

| 区域 | 组件 | 用户任务 |
|---|---|---|
| 侧栏 | SettingsSection + 实时摘要 | 在录音、服务、文件之间定位，并看到当前健康状态 |
| 录音 | MicrophoneStatusRow、输入自检、快捷键、会议模式 | 检查输入、配置录音行为、理解双轨权限 |
| 服务 | APIKeyField、Endpoint/Model 字段 | 配置 OpenAI-compatible ASR/LLM，默认只保存本机 |
| 文件与隐私 | 导出目录、原始文件路径 | 确认原始音频位置和导出边界 |
| 底部操作栏 | 保存本页、还原本页、错误/未保存提示 | 区分草稿和已提交事实，避免跨分区绑定 |

## 状态与文案

- 麦克风状态必须同时有图标、标题、采样率/声道或下一步提示。
- “测试输入”只录制短暂临时 WAV，显示实际帧数/时长/峰值，不进入历史或外发。
- 权限已允许但无输入路由时，提供“打开声音设置”直达按钮；用户选择输入设备后可在同一行点击刷新。
- Endpoint 已填但模型为空时就地报错，保存按钮不产生虚假成功。
- 系统音频无目标时说明解锁桌面、退出远程桌面并重新检查；麦克风轨道状态独立保留。
- API Key 默认隐藏，显示/隐藏是显式动作，仍只进入 Keychain。
- 三个设置分区共用整页草稿快照，但分别维护提交基线；编辑时不改 AppState，只有当前分区候选快照成功写入 Keychain 和本地配置后才提交。
- 底部按钮使用“保存本页/还原本页”；保存录音或文件分区不会校验、读取或写入模型分区的 API Key。
- 保存失败保留可修正草稿，快捷键和下一次录音继续使用最近一次成功保存的设置。
- 语言转文字区提供“测试转写 API”动作；只发送本机生成的短测试 WAV，显示目标主机和 HTTP 结果，不把测试响应写入历史。
- AI 笔记在详情页优先展示可扫读的要点和待办，完整 Markdown 作为可选原文保留，避免把高频信息埋在一整段等宽文本里。

## 可访问性与响应式

- 支持浅色、深色、高对比、键盘导航、VoiceOver 和 Reduce Motion。
- 状态卡使用语义色之外的图标和文字，红色仅用于错误/正在录音。
- 设置窗口最小 760 × 560 pt；侧栏约 220 pt；Popover 336 pt。
- 不把错误只放在 toast；保存失败、权限失败和音频失败在当前页面持久可见。

## 验收证据

- 核心命令：make acceptance-core。
- 完整门禁：make verify。
- 真实桌面按钮、VoiceOver 和系统音频目标仍需解锁 Mac 后人工验收。
