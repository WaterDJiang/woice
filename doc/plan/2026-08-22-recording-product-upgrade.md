## 1. 计划定位

本文档不创建新的并行产品阶段、实施编号或独立工期。它把 App Store 评论中反复出现的失败模式转成 Woice 当前路线图中现有工作包的验收门禁；排期、状态和工期只看[当前路线图](2026-08-22-current-roadmap-and-plan-transition.md)及它指向的权威工作包。

核心判断：

- 用户首先购买的是“录音不会丢”的信任，其次才是转写和摘要。
- 本地处理、无追踪、无隐藏订阅是可感知的产品价值，不只是技术实现。
- 转写错误不可避免，但原音频安全、可重转写、可比较和可导出必须是确定性能力。
- 快速入口保持克制；模型、历史和素材管理进入统一工作台。
- Woice 的竞争优势是开放素材和来源可追踪，不是把用户锁在专有分享或 Agent 入口中。

## 3. 升级目标

### G1：录音事实可信

- 开始后 300 ms 内提供可见状态、计时和输入电平反馈。
- 停止时先提交音频文件和数据库事实，再展示成功。
- ASR、模型下载、Agent 或网络失败均不得删除、覆盖或隐藏原始音频。
- App 重启后能区分已保存、待转写、转写失败和可恢复录音。

### G2：本机转写可衡量、可重做

- 每个候选默认模型使用固定中文、英文、中英混合、多人、噪声和长音频语料测量。
- 保存 Provider、模型 ID、revision、数据位置、参数和处理时间快照。
- 切换模型后的重转写创建新 Transcript/Artifact，并保留父子关系。
- 本地失败只报告本地失败，不自动切换云端。

### G3：发行与隐私承诺可理解

- Core 明确“不含模型、体积较小、可连接或下载模型”。
- Offline 明确“包含默认模型、下载更大、断网可用”。
- 首次外发前显示目标、数据类型和处理位置；授权按 Provider 保存。
- 不使用“无限”“完全离线”等无法由运行时和网络探针证明的文案。

### G4：素材开放、可继续使用

- 用户可独立导出原音频、原文、带时间戳数据和 Markdown。
- 导出文件不要求接收方安装 Woice、登录账号或打开专有链接。
- 搜索、标签、复听和来源信息不依赖 Agent。
- 最近结果复制不超过两次操作；完整导出不超过三次操作。

## 4. 非目标

- 不新增 Woice 自有摘要、待办、通用 LLM Prompt 或 Agent Loop。
- 不自动加入会议、联系参与者或代表用户发送邮件。
- 不以 Apple Watch、专用硬件或云端账号作为核心闭环前置。
- 不在运行时下载并加载任意 dylib、Swift bundle 或未知模型执行代码。
- 不引入隐藏分钟额度或强制订阅。
- 不把说话人分离、摘要质量或外部 Agent 成功率设为核心录音发布前置。

## 6. 并入现有工作包的验收门禁

### 可靠录音与恢复门禁

归属：R0，最高优先级。

- 固化用户动作、录音中、正在提交、已保存、待转写和失败但安全六类状态。
- 验证麦克风、系统声音双轨分别提交；单轨失败时明确保留另一轨。
- 会议记录以“至少一条原始音轨有效”判定可用，不再以麦克风是否有声作为整场会议的唯一成功条件。
- 固化麦克风与系统声音的共享 Session 时钟、首帧偏移、时长、帧数和信号元数据。
- 覆盖休眠/唤醒、输入设备移除、权限变化、磁盘不足、App 退出和进程崩溃。
- 恢复时只依据已提交文件、SQLite Job/Event 和 Lease，不用内存状态推断成功。
- 错误文案回答：发生什么、音频是否安全、下一步操作。

组件影响：`WoiceAudio`、`WoiceStorage`、`WoiceRuntime`、菜单栏状态与录音详情；不改变 Provider 和 Agent 边界。

退出条件：录音中断矩阵全部完成真实 Mac 验证；发现不可恢复音频丢失时停止后续模型与素材升级。

权威工作包：M1-02、M2-01、M2-03；工期不在本文档重复估算。

### 转写质量与模型回归体系

归属：M2-08c/M2-08i。

- 建立无真实隐私的固定语料：普通话、中英混说、英文、双人、远场、噪声、静音和长音频。
- 统一记录 CER/WER、漏句、重复、幻觉、时间戳偏差、RTF、首载、峰值内存和包体积。
- 对 macOS Speech、WhisperKit Tiny、large-v3/turbo 候选使用相同输入和运行条件。
- 把模型 revision、Tokenizer、运行设备和参数写入报告。
- 为重复首句、空输出成功、静音幻觉和长任务 Lease 过期增加专项回归。
- 通过受控音频准备层对齐麦克风 WAV 与系统 CAF，生成固定增益、防削波、可重建的 meetingMix，不覆盖原文件。
- 默认完整会议模式为麦克风/系统音频分别创建 ASR Job 并按时间线合并；`standardMix` 才为 meetingMix 创建一条兼容 ASR Job。
- 用户显式选择“来源分离”时，才为麦克风/系统声音创建独立、可恢复的 ASR Job，并按 Session 时间线合并带来源原文。
- 不静默根据回声、VAD 或 Provider 失败切换转写模式。

组件影响：`WoiceProviders`、模型库存、ProcessingTask 快照、Fixtures 和 Acceptance Harness。

退出条件：默认模型有可复跑报告；无法达到 RTF/内存门槛时更换候选模型，不放宽数据安全门槛。

权威工作包：M2-08a/b/c/h/i；工期不在本文档重复估算。

### Core/Offline 信任型首启与设置

归属：M2-08g/M2-08h。

- 首启第三步显示当前版本、模型是否已安装、体积、处理位置和推荐动作。
- Core 提供“连接已有服务”“下载推荐模型”“稍后设置”三条路径。
- Offline 首次运行先校验 bundled 模型，再允许进入“可本机转写”状态。
- 模型卡片显示安装来源、revision、磁盘占用、健康和当前选择。
- 云端 Provider 第一次外发使用独立确认，不与本机失败提示混在一起。
- 文案使用“正在本机转写”“将音频发送到……”等用户语言。
- 按第 7 节的截图审计重整设置页顶部状态、语言选择、会议模式权限与外部 API 表单。

组件影响：首启、模型与转写设置、ProviderConnectionWizard、健康摘要和 DistributionManifest。

退出条件：两名首次用户无需解释即可区分两版、连接已有模型或完成默认模型启用；无模型时仍能录音和复听。

权威工作包：M2-08e/f/g/i；工期不在本文档重复估算。

### 开放素材与无锁定导出

归属：R2。

- 录音详情区分原音频、原始转录、重转写版本和派生结果。
- 会议详情默认表现为一条 Recording、一个统一回放器和合并原文；麦克风/电脑声音原轨可展开单独复听，`meetingMix` 作为回放/兼容模式产物。
- 统一回放文件是可删除、可重建的 `meetingMix` 派生物，不得替代或导致删除麦克风 WAV 与系统声音 CAF。
- 标准原文/时间戳 JSON 标记 meetingMix 模式，不伪造原轨来源；来源分离版本才保留“我的麦克风/电脑声音”；原始双轨和合成回放均可显式导出。
- 支持原音频、TXT、时间戳 JSON、Markdown 单项与组合导出。
- 导出清单记录 Artifact ID、父子关系、模型快照和创建时间，但不写入凭据。
- 搜索结果能定位录音、Transcript 和时间戳片段；点击后可复听原音频。
- 分享结果不依赖 Woice 账号、专有网页或接收方登录。

组件影响：`WoiceStorage`、Artifact 投影、FTS、导出 Provider、统一工作台；Connector 继续只调用 WoiceRPC。

退出条件：没有网络和 Agent 时完成“搜索 -> 复听 -> 导出 -> 系统应用打开”。

权威工作包：M1-04、M2-03、M2-08h 及 R2 退出检查；工期不在本文档重复估算。

### 版本风险与发布观察

归属：R0/M2-08/R2 各自退出检查，不单独形成阶段。

- 每个候选发布 Build 完成录音、转写、模型切换、导出四条核心 Journey。
- 为最近两个版本保留可回滚模型和数据迁移兼容证据。
- 发布后按版本观察录音丢失、转写卡死、模型下载、导出失败和隐私投诉。
- 评价提示只在用户完成一次安全录音并主动使用结果后出现；失败流程不打扰评分。

退出条件：阻断级问题为 0；任何录音丢失或隐式外发直接阻止发布。

权威工作包：M1-07、M2-08i 及 R2 退出检查；工期不在本文档重复估算。

## 7. UI/UX 升级清单

### 菜单栏

- 空闲：产品状态、一个录音主动作、Profile、最近结果和工作台入口。
- 录音中：红色图标、真实 PCM 时长、输入电平、系统声音轨道状态和停止动作。
- 提交中：显示“正在保存录音”，不提前显示成功。
- 处理中：超过 3 秒显示本机转写/等待模型阶段；用户仍可复听已保存音频。
- 失败：持续显示错误与恢复动作，打开 Popover 不清空。

### 统一工作台

- 历史列表优先显示时长、录制时间、是否有原文、处理位置和模型。
- 详情页先展示复听与原文，再展示重转写、导出和可选 Agent 动作。
- 双轨会议只显示一条历史素材；默认统一回放和标准会议原文，不伪造原轨来源；来源分离版本才显示“我的麦克风/电脑声音”。
- 不把摘要、聊天或“发送给 Agent”放在录音详情主动作之前。

### 模型与转写

- 顶部使用“可本机转写/需要模型/外部服务待确认”。
- 下载只在实际活动模型上显示进度；等待项不伪装成下载中。
- 切换模型说明“只影响后续转写和新的重转写，不改变已有原文”。
- 删除当前模型前说明替代路由；不会删除用户录音。

### 截图一：设置页顶部状态图标

可见问题：窗口顶部中央只有一个窄胶囊和勾选图标，没有文字、上下文或明显的可点击含义。它同时像按钮、保存状态和系统状态，用户无法判断是否需要操作；图标与“保存设置”相距过远，也无法建立因果关系。

设计裁决：

- 移除顶部中央的孤立图标和窄胶囊，不用 icon-only 方式表达全局保存或操作结果。
- 如果它表示保存结果，统一移动到底部操作栏、紧邻“保存设置”，显示“已保存”+ `checkmark.circle.fill`，2 秒后恢复为普通安全说明。
- 如果它表示全局异步反馈，使用页面顶部非阻塞状态条，必须同时包含图标、动作结果文字和必要的下一步；不得只显示一个勾。
- 如果某状态只属于模型、权限或 Provider，就回到对应区块的状态行，不放在窗口标题区域。
- 非交互状态不得使用看起来可点击的胶囊背景；真实图标按钮点击区域至少 32×32 pt，并具备 `help` 与 VoiceOver 名称。
- 保存、未保存、错误三种状态固定在同一位置，避免用户在窗口顶部、页面内容和底部之间寻找反馈。

验收：首次用户看到设置页顶部后不会询问该图标含义；保存设置后能在 3 秒内指出保存结果和生效范围。

### 截图二：语言与会议录制重组

可见问题：识别语言是自由文本框，界面直接出现两个 `zh`，既像重复值也要求用户理解语言代码；“录制系统音频（会议模式）”开关与下方系统音频权限/能力检查分处两个 Section，用户容易误以为打开开关即已具备权限。

页面结构调整：

```text
转写偏好
  识别语言        [自动检测（推荐） ▾]
  自动复制原文    [开关]
  更多转写选项    [展开]

系统声音录制
  录制电脑播放的声音（会议录制） [开关]
  屏幕录制权限    已授权 / 需要授权    [前往系统设置]
  系统能力        可用 / 未检测到显示器 [重新检查]
  说明：麦克风与系统声音分别保存
```

语言选择规则：

- 新安装默认“自动检测（推荐）”，不用 `zh` 作为默认可见值。
- 使用原生下拉 `Picker`；首层显示自动检测、简体中文、英文、日文等常用语言，其他语言进入可搜索列表。
- 菜单主文案使用语言名称，`zh`、`en` 等代码只作为次要说明或不显示。
- 旧配置 `zh` 保持为“简体中文”，迁移不能把已有明确选择改成自动。
- 自动检测是统一产品语义；Provider 不支持自动检测时，在适配层使用系统首选语言或要求用户明确选择，并在当前行就地说明。
- 本机实时预览与最终转写可使用同一语言偏好，但界面要说明不同 Provider 的支持范围，不能静默改语言。

会议录制规则：

- 把功能开关、屏幕录制权限、系统能力和授权动作合并为一个“系统声音录制”任务区。
- 用户打开开关但尚未授权时，在同一区块显示“需要屏幕录制权限”和“前往系统设置”；不能仅在页面下方另设检查卡片。
- 从系统设置返回后自动重检，同时保留手动“重新检查”。
- 权限已授权不等于已经录到声音；录音时仍显示系统声音轨道状态，停止后以 CAF、时长和峰值为事实。
- 主文案改为“录制电脑播放的声音（会议录制）”，解释性更强；“会议模式”作为场景说明，不作为用户必须理解的内部模式名。
- DRM、无可共享显示器和单轨失败说明放在该区块的辅助文案，不与普通转写选项混成一段长 footer。

验收：用户打开系统声音录制后，3 秒内能回答是否已授权、是否具备能力、麦克风是否仍会录制。

### 外部转写 API：改为原生连接表单

当前实现问题：接口地址、模型、API Key、测试按钮和状态被连续堆在同一个 Section 中；字段宽度、说明和动作层级接近，缺少常见的连接流程，也没有先区分本机、局域网和云端。API Key 的显示按钮虽已具备语义，但整个表单仍像底层参数面板。

目标流程：

```text
外部转写服务（可选）
  1. 服务类型    [OpenAI-compatible ▾]
  2. 服务地址    [https://…                         ]
     数据位置    这台 Mac / 局域网 / 云端
  3. 模型         [从服务读取 ▾] 或 [手动填写]
  4. API Key      [••••••••••••                 👁]

  [测试连接]    未测试 / 测试中 / 连接成功 / 可修正错误

  高级选项 ▸
```

表单规范：

- 使用 macOS `Form`/`LabeledContent` 的稳定双列对齐：左侧标签固定视觉宽度，右侧控件占剩余宽度；不让字段和说明在每一行改变起点。
- 默认只显示服务类型、服务地址、模型、API Key 和测试连接；路径补全、语言覆盖等低频参数进入“高级选项”。
- “接口地址”改为“服务地址”，用示例说明既可填根地址也可填完整转写路径；非法 URL 在字段下就地提示。
- 模型优先从服务发现结果使用下拉选择；不支持发现时显示可编辑文本框，并给出格式示例。
- API Key 使用标准 `SecureField`，显示/隐藏按钮位于字段尾部；本机或声明不需要密钥的服务显示“无需 API Key”，不制造必填感。
- 根据 Endpoint 自动显示“这台 Mac/局域网/云端”文字 Badge；保存前不依赖用户理解 Provider 或 Endpoint 术语。
- “测试连接”是表单唯一阶段主动作；测试中禁用重复点击，结果固定显示在按钮下方，不用短暂 Toast 代替。
- 测试成功只说明连接和固定测试音频通过，不等于设置已保存；底部仍由“保存设置”提交草稿。
- 测试说明继续明确“只发送本机生成的短测试音频，不发送历史录音”。
- 外部服务未启用时可以折叠整个表单，只显示当前状态和“添加转写服务”，降低本机用户的信息负担。

组件化边界：

- `LanguagePreferencePicker`：展示语言名称、自动检测和 Provider 支持说明；不决定运行时路由。
- `SystemAudioPermissionCard`：组合开关、权限、能力和恢复动作；不直接访问 ScreenCaptureKit。
- `ProviderConnectionForm`：复用外部 ASR 与仍保留的兼容服务连接布局；不直接写 SQLite/Keychain。
- `ProviderHealthRow`：显示未测试、测试中、成功和可修正错误；不构造网络请求。
- 只有出现第二个使用点或现有 View 超过项目阈值时才抽共享组件，不建立通用表单框架。

验收：用户能按视觉顺序完成填写、测试、保存；Tab 焦点顺序一致；VoiceOver 能读出字段标签、是否必填、错误和测试结果。截图只能验证布局，键盘与 VoiceOver 必须在真实 App 复验。

## 8. 技术栈与组件边界

| 层 | 使用技术 | 本计划职责 |
|---|---|---|
| UI | SwiftUI + AppKit | 状态、首启、模型管理、素材详情和可访问性 |
| Audio | AVFoundation + ScreenCaptureKit | 麦克风/系统声音采集、共享时钟、双轨固化、标准化与派生合成回放 |
| Runtime | Swift Actor + durable Job/Lease | 状态机、恢复、按模式/轨道幂等、Provider 路由、模型快照、meetingMix 标准原文和可选来源合并 |
| Storage | GRDB/SQLite WAL + 文件系统 | Recording/Artifact/Transcript 真相源、FTS、迁移 |
| ASR | macOS Speech + WhisperKit + OpenAI-compatible HTTP | 本机/显式外部转写与标准结果转换 |
| Packaging | SwiftPM + 签名 Manifest + DMG | Core/Offline 资源差异、模型哈希、SBOM、签名公证 |
| Validation | XCTest + Fixtures + 真实 Mac Acceptance | 中断、音频、模型性能、隐私、导出和发布 Journey |

依赖继续保持：Domain <- Audio/Storage/Providers <- Runtime <- UI <- App。UI 不直接读 GRDB、文件、音频设备或 URLSession。

## 10. 验收矩阵

| 场景 | 必须结果 |
|---|---|
| 无模型开始并停止录音 | 音频可复听，状态为待选择模型，不报录音失败 |
| 本机模型转写崩溃 | 原音频和旧原文不变，可换模型创建新转写 |
| 云端 ASR 已配置但未授权 | 不发请求，显示目标和确认动作 |
| 系统声音轨失败 | 麦克风轨继续提交，明确说明系统轨未保存 |
| 麦克风静音、系统声音有效 | 会议仍保存成功，只创建系统声音 ASR Job 并产生来源明确的原文 |
| 麦克风与系统声音都有效，默认完整会议模式 | 创建两条原轨 ASR Job，按时间线合并为一份不伪造原轨来源的会议原文 |
| 麦克风与系统声音都有效，来源分离 | 两条独立 ASR Job 成功，带时间戳结果按共享时间线合并且保留来源 |
| 用户统一复听会议 | 使用可重建的 meetingMix；麦克风 WAV 与系统声音 CAF 原件及 SHA-256 不变 |
| 外部 ASR 处理会议 | 首次发送前显示目标、原始数据类型、实际文件数和请求数；标准模式为 1，来源分离为 2，取消为 0 |
| App 在提交或转写中退出 | 重启后根据文件/Job 恢复，不伪造成功 |
| Offline 断网首次启动 | 校验 bundled 模型并完成本机录音转写 |
| Core 未配置模型 | 首启可跳过模型，录音与复听完整可用 |
| 切换模型重转写 | 新 Artifact 保存新快照，原音频 SHA-256 不变 |
| 导出素材 | 系统应用可独立打开，接收方不需要 Woice 账号 |
| Agent 未安装或失败 | 录音、转写、复听、搜索和导出不受影响 |
| 设置页顶部出现保存反馈 | 底部操作栏显示“已保存”文字与图标；顶部无孤立状态图标 |
| 新安装打开录音设置 | 语言显示“自动检测（推荐）”，使用下拉列表而不是自由文本 |
| 开启系统声音但未授权 | 同一区块显示权限状态和授权动作，不把开关与权限拆开 |
| 配置外部转写服务 | 按服务地址、模型、密钥、测试顺序完成；测试成功后仍需保存草稿 |

## 11. 风险与裁决

- 大模型性能不达标：选择更小默认模型，不放宽 RTF/内存和音频安全门槛。
- 中国区模型或许可证不适合分发：Offline 从目标地区移除该模型包，Core 保留用户连接能力；先完成法律与权重审查。
- 开放导出扩大隐私面：只由用户显式触发，导出前显示数据类型，不自动同步外部目录。
- 评价样本偏向极端用户：评论只决定风险优先级，最终方案仍以真实 Journey、定量基准和盲测为准。
- 工作包与旧计划重叠：按归属回写到唯一现有阶段，不新建第二套 Runtime、Registry、素材模型或导航。
