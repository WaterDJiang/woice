## 1. 计划定位

本计划只处理五个连续问题：

- 菜单栏弹窗与顶部状态项距离异常，空闲态出现大块无意义空白。
- 菜单栏承担了品牌说明、状态、最近结果和多层“更多”操作，偏离快速控制器定位。
- 设置页默认暴露过多实现术语；快捷键只能从三个预设中选择，不能直接录入和保存前检查冲突。
- Dock 中的 Woice 图标显示为无圆角白色方块，与相邻 macOS App 图标的系统形状不一致。
- 录音详情混用“会议回放、复听、电脑播放的声音、声音片段”四种命名维度；合并音频生成后又可能停在含糊的“发送录音并转写”确认，用户无法确认将转写哪条音轨、为何没有自动继续。

本计划不改变录音、转写、素材、权限、Agent、模型下载和 Artifact 业务语义，不新增插件市场或用户可执行脚本。

## 2. 审计结论与根因

### 2.1 菜单栏弹窗

- 截图中 Popover 箭头紧邻菜单栏，但真实内容从窗口下半段才开始；问题不是按钮 `padding`。
- `WoiceMenuBarController` 固定设置 `popover.contentSize = 336 × 560`，而 SwiftUI 根视图只固定宽度、没有填满或回传实际内容高度。
- 空闲内容的固有高度小于 560 pt，AppKit 仍保留完整窗口高度，形成顶部大块空白。
- 现有弹窗同时包含品牌头、状态卡、主按钮、最近结果、“查看全部录音”和“更多”菜单；用户需要在两层入口中寻找工作台、设置和退出。

### 2.2 设置页

- “录音与输入”首屏同时呈现本机保存承诺、麦克风诊断、语言、复制/粘贴、`verbose_json`、`on-device Speech`、快捷键、系统音频和辅助功能权限。
- 多条长期静态说明重复解释安全边界，挤压真实设置项；实现术语进入默认层级。
- `SettingsView.swift` 当前约 1,879 行，已有多个独立 Pane，但页面内容仍以不断追加 Section 的方式增长，缺少“常用/高级”信息层级。

### 2.3 快捷键

- 现有 `RecordingShortcut` 是四选一枚举：`⌥Space`、`⌃⌥Space`、`⌘⌥Space`、关闭。
- 当前冲突只在保存后重新注册时发现；用户无法直接按下想要的组合，也不能在保存前确认候选快捷键是否可注册。
- Carbon 注册方式本身可继续复用，无需 Event Tap 或输入监控权限；需要补的是数据表达、录入控件、候选探测与原快捷键回滚。

### 2.4 Dock 图标

- 当前安装包已经包含 `Assets.car`、`AppIcon.icns`，Info.plist 也正确声明 `CFBundleIconName/AppIconFile=AppIcon`，因此不是缺少 Bundle 图标元数据。
- 生产 `woice-app-icon-1024.png` 为 1024 × 1024 的完全不透明白底 PNG，安装包内文件与生产导出 SHA-256 一致。
- `WoiceBrandAssets.installApplicationIcon()` 启动时把这张原始 PNG 赋给 `NSApplication.shared.applicationIconImage`；该运行时覆盖会绕开或覆盖 Bundle AppIcon 的系统呈现，直接解释 Dock 中的白色方块。
- 现有品牌 README 写“App Icon 由系统负责圆角遮罩”，但同时又在运行时塞入扁平 PNG；两个策略冲突，必须只保留一条发布真相。

### 2.5 录音来源与回放

- “复听”是操作名称，不是音频来源；与“电脑播放的声音（独立音轨）”并列后，用户无法判断前者其实是麦克风原始录音。
- “会议回放”表示合并后的派生音频，但页面没有直接写出它由“我的声音 + 电脑声音”组成，也没有与两条原始音轨形成清晰层级。
- “声音片段”是本机声音活动检测结果，不是第三条音轨；当前与三个播放器处于同一视觉层级，容易被误认为另一种录音。
- 默认说明直接暴露 WAV、CAF、标准模式等实现信息，增加理解成本；文件格式应进入技术详情，默认层只说明来源、用途和是否为原始音轨。
- 当前代码能够在标准模式选择 `meetingMix`，但弹窗标题固定为“发送录音并转写”，取消按钮固定为“仅保存录音”；它没有说明正在处理合成回放、本机服务还是外部服务，也把已经保存完成的素材误写成尚未保存。
- 本机只读事实检查确认存在两种不同记录：一条已生成合并音频但任务停在等待确认、尚无原文；另一条虽然保留电脑声音文件，但峰值为 0、没有有效系统声音，因此没有生成合并音频并回退到麦克风转写。当前界面没有把这两种状态讲清楚。
- 当前设置显式选择了 `127.0.0.1` 的 OpenAI-compatible 服务；数据位置已被代码识别为本机，但处理仍复用“外发”弹窗。这是合并音频没有继续转写的直接流程阻塞，不是 `meetingMix` 选择算法完全缺失。
- 新截图已能正确写出“会议完整回放”，但依然以模态 Alert 覆盖菜单栏四动作，并继续使用“目标：127.0.0.1”“继续发送”；来源文案修正了，任务连续性没有修正。
- 根因是 `verifiedLocalASREndpoints` 只保存在当前 `AppState` 的内存 `Set`。用户在设置中完成健康检查后，本次进程可以自动转写；App 重启或重新安装后验证事实丢失，同一个 loopback 服务再次退回逐条确认。
- “稍后处理”当前调用 `dismissExternalProcessing()` 并把任务写成 `cancelled`，与“稍后可继续”的承诺不一致；它不是暂停或排队。
- 最新记录已经存在一个等待确认的会议完整回放任务，同时又出现一个等待确认的声音片段任务。页面没有阻止同一素材在主转写未完成时继续创建另一条竞争任务，用户会连续遇到多个确认弹窗。

## 3. 目标与成功标准

### 3.1 菜单栏

- 空闲态只保留四个动作：开始录音、进入工作台、设置、退出 Woice。
- 录音时第一个动作原位变为“结束录音”，并保留必要的计时和录音可见状态。
- 处理、等待确认或失败时只增加一条紧凑状态提示，不恢复最近结果卡或多层“更多”菜单。
- Popover 高度跟随内容，箭头下方到首个可见内容的空白不超过 20 pt。

### 3.2 设置页

- 默认首屏只展示用户能直接决策或立即处理的内容。
- 技术细节、诊断说明和低频能力进入“高级设置”或按需展开；错误与权限恢复仍在需要时就地出现。
- 默认文案不出现 `verbose_json`、`CAF`、`on-device Speech`、`Provider`、`Keychain` 等实现词；高级层仍可查看准确事实。
- 保留分区独立保存、失败回滚和密钥存储边界。

### 3.3 快捷键

- 用户可聚焦录入框后直接按下一个标准组合键，也可清除并关闭快捷键。
- 候选快捷键在保存前显示“可用 / 已被占用 / 系统保留 / 不支持”。
- 保存切换必须原子化：新快捷键注册失败时恢复旧快捷键，不留下两个快捷键或无快捷键的中间态。
- 旧设置中的三个预设和关闭状态无损迁移。

### 3.4 Dock 图标

- Dock、Finder、Launchpad 和应用切换器使用同一个 Bundle AppIcon，不再被运行时原始 PNG 覆盖。
- 图标呈现符合系统圆角矩形轮廓，白色背景不再显示为硬直角方块。
- W 主标在 16、32、64、128 和 1024 px 下保持居中、清晰且不被系统遮罩裁切。
- 菜单栏继续使用单色 SF Symbol；Popover 内品牌标识仍可使用现有彩色资源，两者不与 App 图标混用。

### 3.5 录音来源

- 用户无需理解 WAV、CAF 或 `meetingMix`，即可辨认“我的声音（麦克风）”“电脑声音”和“会议完整回放”。
- 两条原始音轨与合成回放使用文字 Badge 明确标注“原始音轨 / 合成回放”，不依赖颜色判断。
- 默认转写来源在播放器附近明确显示，例如“当前转写来源：会议完整回放”；来源分离模式则明确显示“两条原始音轨分别转写”。
- “检测到的有声片段”进入转写分析或折叠详情，不再与录音轨道并列。
- 标准模式下，两条原始音轨有效时默认对“会议完整回放”只转写一次；本机模型和已验证的本机服务不要求用户每条录音重复确认。
- 系统声音无有效信号或合并音频生成失败时不得静默改成麦克风转写；必须先显示“本次仅转写我的声音”及原因。

## 4. 目标菜单结构

### 4.1 空闲态

```text
┌──────────────────────────────┐
│ [ 开始录音 ]                 │  主动作
│  进入工作台                  │
│  设置                        │
│ ─────────────────────────── │
│  退出 Woice                  │
└──────────────────────────────┘
```

### 4.2 录音与异常状态

- 正在录音：顶部仅显示红色状态、真实时长和必要的输入状态；主按钮为“结束录音”。
- 正在处理：顶部显示当前阶段和“原始录音已保存在本机”；四个动作仍保持原顺序。
- 等待外发确认：显示“等待你确认”，点击“进入工作台”打开对应任务或素材上下文。
- 失败：显示一条短错误和“进入工作台处理”的恢复方向；完整诊断留在工作台。
- 首次引导迁移到工作台首启流程，不再改变菜单栏的尺寸与操作顺序。

### 4.3 命令组件边界

- `MenuBarPopover`：只负责宽度、动态高度、状态区与命令区组合。
- `MenuBarStatusView`：只表达录音、处理、等待确认和失败事实。
- `MenuBarRecordingAction`：复用既有开始/停止录音入口和退出前安全保存语义。
- `MenuBarCommandList`：统一渲染工作台、设置和退出动作。
- `MenuBarCommand`：使用受控枚举或值类型描述 `id/title/systemImage/role/isEnabled`；顺序集中在一个静态清单中。

该组件化只服务现有第二个使用点和频繁顺序调整，不引入动态配置文件、插件协议或任意命令执行。

## 5. Popover 尺寸策略

- 宽度继续使用 336 pt，保持现有 Quiet Native Utility 基线。
- 移除固定 560 pt 高度；由 `NSHostingController` 的实际 `fittingSize` 回传 Popover 高度。
- 空闲态高度目标为 190～260 pt；录音/错误/等待态按内容增长，但上限为 420 pt，超出部分只允许状态详情滚动。
- 状态变化后重新测量尺寸，不通过透明占位或固定 `Spacer` 保持旧高度。
- 在菜单栏位于主屏、副屏、刘海屏两侧和不同缩放比例时复验锚点；不得把 Popover 误判为“距离图标远”。

## 6. 设置页信息减负

### 6.1 默认层

| 页面 | 默认展示 | 收起或迁移 |
|---|---|---|
| 录音与输入 | 麦克风状态、录音快捷键、识别语言、自动复制、录制电脑声音 | 时间戳格式、实时预览实现、输入帧/采样率、权限原理 |
| 模型与转写 | 当前转写方式、当前模型、切换入口、外部服务是否已配置 | Endpoint/模型 ID、Catalog、版本清单、健康诊断和服务预设 |
| 文件与隐私 | 素材保存位置、导出位置、必要权限状态 | 文件格式术语、内部目录结构、Keychain 实现说明 |
| 高级功能 | 默认折叠，明确标记“高级”或 `Beta` | Agent/CLI、服务发现、开发诊断和兼容参数 |

### 6.2 文案规则

- 常态只写“这是什么”和“改了会怎样”；权限原理、安全实现和恢复步骤按状态出现。
- 把“保留转写时间戳（verbose_json）”改为“保留逐句时间”；实现格式放入 Help。
- 把“录音时显示本机实时转写预览”改为“录音时预览文字”；本机实现放入 Help。
- 把“系统音频能力可用”改为“可以录制电脑声音”；显示器数量、CAF/WAV 和受保护媒体限制移入详情。
- 默认页脚不重复声明“不访问 API Key 或 Keychain”；只有保存密钥、外发或权限异常时显示对应说明。
- 保留失败要响亮：错误文案仍说明发生什么、素材是否安全、下一步动作。

## 7. 自定义快捷键与冲突检查

### 7.1 数据迁移

- 保留 `RecordingShortcut` 领域名称，但从固定枚举迁移为可编码的“键码 + 修饰键 + 显示名称”值。
- 旧值 `optionSpace`、`controlOptionSpace`、`commandOptionSpace`、`disabled` 在解码时映射到新结构；不要求用户重设。
- 禁止只有修饰键的组合；至少包含 `Command`、`Option`、`Control` 或 `Shift` 中一个修饰键和一个普通按键。
- `Escape` 用于取消录入；`Delete/Backspace` 用于清除，不保存为快捷键。

### 7.2 录入体验

- 设置项显示当前快捷键和“点击后直接按下新组合”的录入区域。
- 录入期间显示“正在等待快捷键…”，成功后展示规范化符号，不立即提交运行时设置。
- 提供“重新输入”和“关闭快捷键”；不再用只能选择三个值的下拉菜单作为主入口。
- 控件必须有 VoiceOver 名称、当前值、录入状态和错误说明；键盘焦点不得被永久困在录入模式。

### 7.3 冲突检查

保存前按以下顺序检查：

1. 校验组合格式和产品禁用清单。
2. 识别 Woice 当前已注册组合；候选与当前相同直接视为可用。
3. 用独立临时 HotKey ID 尝试 Carbon 注册；成功后立即注销探针。
4. `eventHotKeyExistsErr` 显示“已被其他应用占用，请换一个组合”。
5. 保存时先准备新注册，再提交设置；任何失败都恢复旧快捷键和旧持久化值。

边界：Carbon 只能确认注册式全局快捷键冲突，不能证明所有应用内菜单快捷键或第三方底层监听均不存在；界面使用“当前可注册”，不承诺“全系统绝无冲突”。

## 8. Dock 图标策略

### 8.1 单一发布真相

- App 图标只以 Bundle 中的 `AppIcon` 为系统发布真相；生产启动路径停止调用 `NSApplication.shared.applicationIconImage` 覆盖 Dock 图标。
- `woice-app-icon-64/1024.png` 继续作为 Popover、品牌预览和资源审计素材，不再控制 Dock/Finder/Launchpad。
- Core、Offline、Development、稳定 A/B 与后续 Store Edition 共用同一 AppIcon 源，不生成发行版专属外形。

### 8.2 系统遮罩与 Icon Composer

- 第一阶段先移除运行时覆盖，重新打包并让 macOS 使用现有 Asset Catalog/Bundle AppIcon；不预先烘焙一个人工圆角。
- 若受支持 macOS 版本上的真实 Dock/Finder 仍显示方形，再把 W 前景与全幅白色背景迁移到 Icon Composer 分层资源，由系统应用圆角、材质和外观变化。
- 不在 PNG 上叠加随意的 CSS/SwiftUI 圆角，也不同时保留“系统遮罩”和“手工遮罩”两套生产模式。
- W 主标使用 Apple 图标网格检查视觉安全区；白色背景必须是完整背景层，前景边缘保持清晰，避免系统高光下出现羽化白边。

### 8.3 缓存与验收

- 每次安装使用新 Build Number，重新注册 LaunchServices 后退出并重开 Dock/Finder；不得只看 App 内运行时图标。
- 同时截取 Dock、Finder 应用列表、Launchpad/应用切换器和 16/32 px 小尺寸，避免“大图正常、小图变成白块”。
- 对比旧截图时保持相同 Dock 大小和放大设置；检查圆角、视觉尺寸、中心位置、阴影/高光和相邻图标一致性。

## 9. 录音来源与回放语义

### 9.1 固定命名

| 用户可见名称 | 类型标识 | 含义 | 默认说明 |
|---|---|---|---|
| 我的声音（麦克风） | 原始音轨 | 麦克风采集的本人声音 | 录音时通过麦克风收录，只在本机保存和播放 |
| 电脑声音 | 原始音轨 | 会议对方、视频或电脑中播放的声音 | 录音时从电脑输出收录；采集范围异常时就地说明 |
| 会议完整回放 | 合成回放 | 由两条有效原始音轨生成的派生回放 | 合并我的声音和电脑声音，便于完整复听 |
| 检测到的有声片段 | 分析结果 | 本机检测出的有声时间范围 | 不是独立录音，也不是转写文本 |

规则：

- 不再使用只有动作含义的“复听”作为区块标题；播放、暂停和停止仍作为每条音轨的控件。
- 默认标题和说明不显示 WAV、CAF、`meetingMix`、Buffer 或峰值；这些事实进入“技术详情”，错误诊断需要时可就地展示。
- 界面文案统一使用“我的声音”，来源分离的转写标签也使用同一名称；内部 `microphone/systemAudio/meetingMix` 与不可变 Artifact 契约保持不变。
- 窗口级采集时显示“电脑声音（当前窗口）”，不得声称已录制全系统输出。

### 9.2 信息层级与顺序

详情页的音频区域按同一维度组织：

1. “录音轨道”首先展示两条原始来源：我的声音、电脑声音。
2. 有两条有效原轨时展示“会议完整回放”，并标记为“合成回放”。
3. 转写区显示当前转写来源；标准模式写“会议完整回放”，来源分离模式写“我的声音 + 电脑声音”。
4. “检测到的有声片段”移动到“转写分析”折叠区，避免成为第四种录音来源。

只有麦克风的普通录音只显示“我的声音（麦克风）”，不生成空的“电脑声音”或“会议完整回放”卡片。播放器复用同一共享组件，来源名称、类型 Badge、时长和状态由受控投影传入；不为三种音频复制三套交互。

### 9.3 状态与无障碍文案

- 电脑声音缺失：写“未录到电脑声音；我的声音已安全保存”，同时说明重新授权或检查采集范围的下一步。
- 合成回放失败：写“会议完整回放生成失败；两条原始音轨仍可分别播放”，不把派生失败描述为录音丢失。
- VoiceOver 组合朗读来源与类型，例如“我的声音，麦克风原始音轨，播放”和“会议完整回放，合成回放，播放”。
- 原始/派生状态必须同时用文字和图标表达；颜色只作辅助。

### 9.4 默认转写与确认语义

标准模式的确定性顺序：

1. 两条原始音轨有效 -> 生成会议完整回放 -> 创建唯一 `meetingMix` 转写任务 -> 按当前转写方式开始处理。
2. 只有麦克风有效 -> 明确显示“未录到电脑声音，本次仅转写我的声音” -> 创建麦克风转写任务。
3. 只有电脑声音有效 -> 明确显示“未录到我的声音，本次仅转写电脑声音” -> 创建电脑声音转写任务。
4. 两条原轨有效但合成失败 -> 保留两条原轨并显示失败，不自动用麦克风结果冒充完整会议原文。

按处理位置区分交互：

| 当前转写方式 | 默认行为 | 用户可见文案 |
|---|---|---|
| Woice 内置本机模型 | 录音停止并安全落盘后自动转写 | 正在转写会议完整回放 |
| 已显式选择且健康检查通过的 `localhost/127.0.0.1/::1` 本机服务 | 默认自动提交到本机服务；服务失联时保留任务并可重试 | 正在使用本机服务转写会议；音频不会离开这台 Mac |
| 尚未验证的本机服务 | 第一次使用前确认，确认后记住该服务选择；不在每条录音上重复询问 | 使用本机服务转写会议 / 开始转写 / 稍后处理 |
| 局域网或云端服务 | 保留实际外发前确认，不自动绕过安全边界 | 将把会议完整回放发送到「服务名或域名」/ 确认发送并转写 / 稍后处理 |

“发送录音并转写”停止作为通用标题；“仅保存录音”改为“稍后处理”，因为录音在弹窗出现前已经安全保存。确认内容必须显示实际输入（会议完整回放/我的声音/电脑声音）、处理位置、文件数和请求数，不显示 WAV、Endpoint 原始地址或 Provider 实现词作为主文案。

重试和恢复必须重新从持久化 Recording 计算有效转写来源，但不得改变用户明确选择的标准/来源分离模式。旧任务若 `idempotencyKey` 已包含 `meetingMix` 但 `sourceTrack` 为空，应在兼容投影中修正为合成回放；同一幂等键只能保留一个有效任务，避免“等待确认”和“已取消”重复条目让状态无法推进。

本机服务信任与菜单栏交互进一步冻结为：

- 本机服务健康检查成功后，持久化不含凭据的授权事实：规范化 Endpoint、模型 ID、配置摘要和确认时间；App 重启、稳定签名覆盖安装和窗口重开不得丢失。
- Endpoint、模型或配置摘要改变时立即失效并要求重新检查；服务暂时离线只让任务失败可重试，不静默改用云端 Provider。
- 菜单栏不再承载会抢走焦点的转写 Alert。本机服务直接进入“正在本机转写”；局域网/云端需要确认时显示紧凑“等待你确认”状态，并由“进入工作台”打开对应任务确认。
- “稍后处理”把任务保留为 `queued/paused` 可恢复状态，不写成 `cancelled`；素材卡和详情页提供唯一“继续转写”动作。
- 一条 Recording 同一时刻只允许一个主转写策略处于等待、运行或恢复状态。标准会议转写未结束时禁用“按声音片段转写”；改用片段或来源分离必须作为显式“新建转写版本”，不能插入当前确认队列。
- 本机服务界面写“使用本机服务转写”，不写“发送到 127.0.0.1”；技术地址只在设置或技术详情出现。

- AC-MSS-029：合并音频生成失败时标准模式不静默回退到麦克风原文；两条原轨保持可播放，用户可重试合成或显式改用来源分离。
- AC-MSS-030：历史任务的幂等键为 `transcription:meetingMix` 而 `sourceTrack` 缺失时兼容投影为合成回放；同一幂等键不存在重复有效任务。
- AC-MSS-031：任务在等待确认、处理中或 App 重启后仍能从同一来源继续；完成、稍后处理和失败状态在素材卡与详情页一致。
- AC-MSS-032：loopback 健康检查授权绑定 Endpoint、模型和配置摘要持久化；App 重启和稳定签名覆盖安装后仍能自动处理，配置变化后立即失效。
- AC-MSS-033：已验证本机服务转写不会显示菜单栏 Alert，不出现“继续发送”或裸 `127.0.0.1`；状态写“正在使用本机服务转写会议完整回放”。
- AC-MSS-034：局域网/云端确认不遮挡菜单栏四动作；点击“进入工作台”可定位唯一待确认任务。
- AC-MSS-035：“稍后处理”保留可恢复任务，不写成 `cancelled`；App 重启后可从同一来源继续。
- AC-MSS-036：同一 Recording 只有一个等待/运行中的主转写策略；标准转写未结束时不能追加声音片段转写确认。
- AC-MSS-037：切换为声音片段或来源分离使用“新建转写版本”，原始合并音频和已有原文不覆盖。
- AC-MSS-038：VoiceOver 焦点不会被录音停止后的自动 Alert 抢走；状态变化通过文字和可访问通知表达。
- AC-MSS-039：`make docs-check`、`make harness-check`、`make lint`、`make test`、`make verify` 通过；真实 Popover、快捷键、Dock 和录音来源/合并转写 Journey 单独记录。
