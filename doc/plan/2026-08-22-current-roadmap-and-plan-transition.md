## 1. 使用规则

- 开发前先读本文件，再进入对应专项计划；旧计划中的状态与本文件冲突时，以本文件为准。
- 本文件不替代功能规格、设计和专项验收条件；WCL 编号只编排跨专项收口，底层实施与证据仍回写原工作包/规格，不复制领域任务。
- `继续`：仍可按原工作包实施。
- `迁移`：原目标仍有效，但只能在新的权威工作包中实施。
- `冻结`：保留当前兼容行为，不增加新能力。
- `停止`：原计划已被产品方向替代，不得继续实施。
- `历史`：只用于解释已发生的实现和决策，不是待办来源。

## 2. 当前唯一实施顺序

```text
R0 录音与素材核心收口
  -> R1 M2-08 ASR、模型与 Core/Offline
  -> R2 素材库可复听、可搜索、可引用收口
  -> R3 M2-09 Agent 协作（核心完成后的可选扩展）
```

严格按上图执行。M2-09a 也必须等 M2-08 和 R2 退出检查通过后开始，避免“先做 Agent 契约”挤占录音、模型或素材库收口。

[当前技术开发收口计划](2026-08-24-current-technical-development-closure.md)是跨现有产品阶段的技术收口入口，不新增产品能力阶段，也不改变 R0 -> R1 -> R2 -> R3 的架构顺序。WCL-01～04 收口核心代码与发行工程；WCL-05 保持 Agent 后置；WCL-06 已完成本机 MAS-03/Store 工程切片；WCL-07 新增本机模型一键安装与 Store-compatible Qwen Runtime。真实用户与人工体验验收不进入开发工作包。

Mac App Store 上架是独立发行轨，当前状态为“待实施”，不插入上述产品实施顺序。用户明确启动后，账号、Bundle ID、隐私和素材准备可以独立进行；Store 工程改造与提交必须遵守[Mac App Store 上架计划](2026-08-23-mac-app-store-launch.md)的退出条件。该计划不替代 M1-07 的官网 Developer ID/公证，也不替代 M2-08i 的 Core/Offline 发行门禁。

例外边界：为完成最基本的“录音 -> 文字”核心闭环，M2-08 的本机 ASR 最小 Adapter 可以在 R0 收口期间先落地；它不启动 WhisperKit 权重冻结、模型下载、Core/Offline 打包或 M2-09。M2-08 全量发布仍必须等待 R0 退出检查。

### R0：录音与素材核心收口

继续使用旧总计划中仍有效的原 ID，不创建 `R0-*` 实施项：

- M1 真实 Mac“开始录音 -> 说话 -> 停止 -> 转写 -> 复听”桌面 Journey。
- M2-01 系统音频双轨真实采集与 UI 验收。
- M2-01 同时承接双原轨提交、“至少一轨有效”语义、共享 Session 时钟与首帧偏移；不在新规格中另建录音工作包。
- M2-02 本机实时预览人工验收；云端实时增量 ASR 和说话人分离仍是后续增强，不阻塞单轨核心。
- M2-02/M2-03 本机后台分段转写：已关闭声音片段可在长录音期间串行交给已授权本机模型；外部 ASR 仍在停止后确认外发。
- M2-03 原始 Artifact、时间戳、Job/Lease、失败恢复和素材安全；双轨增量在此扩展 `sourceTrack`、track-aware 幂等键和不可变原件契约。
- M2-04 快捷键与辅助功能真实桌面验收。
- M1-07 Developer ID、Notarization 和发行前隐私门禁；双发行专属门禁由 M2-08i 接管。

R0 不包含新的 LLM 摘要、Prompt 模板、Agent 工具或插件生态。

### R1：M2-08 ASR、模型与双版本

- 唯一实施文件：[M2-08 模型接入与双版本发布](2026-08-22-model-integration.md)；当前已先落本机 ASR 最小闭环，未替代后续 WhisperKit/模型包工作。
- 负责 WhisperKit、ASR Provider Registry、模型包/下载、连接向导、Core/Offline 和无模型补转写。
- 会议双轨不新建模型阶段：M2-08a 承接轨道/转写模式 Schema，M2-08b 承接 meetingMix 回放准备与默认双轨分别转写路由，兼容 `standardMix` 单次路由只保留为显式模式，M2-08h 承接原文版本的“素材可用”状态，M2-08i 承接两种模式的真实会议门禁。
- 不负责通用 LLM、Agent CLI、Agent 结果处理或 TTS Provider 扩展。

### R2：素材库收口

R2 是已有核心工作的退出检查，不是新建的并行项目：

- M1-04 负责历史、搜索、详情、导出、可恢复删除和 Artifact 版本查看。
- M1-04 同时承接“一场会议/一条 Recording”的统一回放、原轨展开、分轨/合成导出和历史表达。
- M2-03 负责原始转录、时间戳、处理恢复和不可变来源链；同时承接会议 Segment 时间线合并与来源投影。
- M2-08h 负责形成“素材可用”状态和稳定只读 Artifact 引用。
- 只有音频可复听、文字可搜索、来源可追溯后，素材才可进入 M2-09。

### R3：M2-09 Agent 协作（核心完成后的可选扩展）

- 唯一实施文件：[M2-09 语音上下文与 Agent 协作](2026-08-22-voice-context-agent-integration.md)。
- 负责 Context Package、受控 CLI 派发、结果 Artifact、MCP/RPC 读取、Agent 权限与审计。
- 不反向实现 ASR、模型下载、录音设备或 Woice 自有 Agent Loop。
- 不作为核心版本发布前置；移除所有 Connector 后，R0/R1/R2 仍必须独立通过验收。

## 5. 当前禁止实施清单

- 不从旧 M1-03 继续新增 Woice 内置摘要、修订、待办 Prompt 或 LLM 工作流。
- 不从旧 M1-06 提前建设 MCP/Agent 能力来阻塞录音和模型发布。
- 不从旧 M2-06 开发云端、本地模型 TTS Provider 或语音克隆。
- 不把 M2-07 的受控进程能力扩展成任意插件或 Shell 执行器。
- 不执行旧 M3 插件目录、Agent 网关或 DeepSeek Harness 阶段计划。
- 不把 M2-09 的“发送给…”放到录音、转写和素材详情之前成为产品主入口。

## 6. 变更门禁

以后新增或修改计划，必须在文件头和 `plan/INDEX.md` 同时写明：

- `替代`：取代哪些计划或工作包。
- `保留`：哪些旧范围继续有效。
- `迁移`：重叠工作由哪个唯一工作包承接。
- `停止`：哪些旧待办不得再实施。
- `顺序`：它在当前路线图中的前置和后置关系。

未写清以上五项的新计划只能标为“草案”，不能进入实施。
