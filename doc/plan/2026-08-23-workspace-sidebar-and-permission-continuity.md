## 1. 计划定位

本计划只处理三类问题：

- 工作区信息架构：把一级功能导航与当前工作区列表合并为一个左侧栏，减少当前“双侧栏”感知和素材列表拥挤。
- 音视频导入连续性：从菜单栏或工作台选择本地文件后，在同一流程中完成导入、立即转写和打开新素材，不要求用户返回列表寻找文件。
- 权限连续性：区分复制、自动粘贴、麦克风、系统声音和语音识别权限，并在稳定代码身份下验证更新/覆盖安装后的授权继承。

本计划不新增 AI 对话、AI 处理工作区、Prompt 模板或 Agent Loop。已有 CLI/Agent 调用继续按 M2-09 的 `发送给 Agent… -> 用户确认 -> 受控 CLI -> 结果 Artifact` 路径演进；前端可见的 CLI 能力统一标记为 `Beta`。第 11 节只保留迁移记录，活动待办统一由 WCL-05 管理。

本计划现只作为 WPC-00～08 的历史实施与验收证据，不再承接活动待办。后续工作统一从 WCL 计划启动。

## 3. 目标与成功标准

### 3.1 工作区目标

- 用户只感知一个左侧栏，不再把功能导航与素材列表理解为两个并列侧栏。
- 用户进入任一工作区后，左侧栏下方立即显示该工作区的对应列表。
- 素材标题、时长、日期、来源和状态不出现纵向挤压或单字换行。
- 未选择素材时，主内容区提供明确的下一步，而不是只显示大面积空白。
- 录音主动作持续可见，工作区改造不改变录音开始/停止语义。
- 素材库和素材详情上下文持续显示“导入音视频…”次级动作；与“开始录音”并列但不争夺主动作层级。
- 文件导入完成后，同一 Sheet 立即提供“转文字”；成功后自动进入素材库并选中刚完成的素材。
- 素材列表和详情明确区分录制、导入音频和导入视频，后续处理仍使用同一套转写、版本、导出与 Agent 基建。

### 3.2 权限目标

- 普通复制无需辅助功能权限；只有自动粘贴才请求辅助功能权限。
- 每项权限显示用途、状态、触发动作、失败原因和恢复路径。
- 使用稳定签名身份后，同一发行渠道的覆盖安装/版本更新不重复请求已经授予的权限。
- 从 ad hoc 开发包切换到稳定签名包时，允许出现一次明确迁移授权，但之后不得每次更新重复发生。
- 不承诺 Developer ID、TestFlight、Mac App Store 等不同发行身份之间自动共享 TCC 授权。

## 4. 目标信息架构

### 4.1 窗口结构（历史信息架构）

> 本节只保留“单一侧栏 + 主内容区”的已实现背景；顶部/中部/底部几何与滚动实现迁入[WCL-01](2026-08-24-current-technical-development-closure.md)，真实截图只作体验提醒。

```text
┌──────────────────────────────┬────────────────────────────────────────────┐
│ 单一左侧栏 300-340 pt         │ 主内容区                                   │
│                              │                                            │
│ 顶部：工作区与工具            │ 素材库：录音详情/空状态                    │
│   素材库                      │ 处理任务：任务概览                         │
│   处理任务                    │ 文字转音频：编辑与导出                     │
│   文字转音频                  │ 设置：当前设置分区                         │
│ ──────────────────────────── │                                            │
│ 中部：当前工作区标题/搜索/筛选 │                                            │
│   当前工作区对应列表          │                                            │
│                              │                                            │
│ 底部：设置/必要状态入口       │                                            │
└──────────────────────────────┴────────────────────────────────────────────┘
```

约束：

- 左侧栏最小 280 pt、理想 320 pt、最大 360 pt；窗口仍遵守现有最小尺寸基线。
- 不增加常驻右侧 AI 面板；已有录音详情继续显示在主内容区。

### 4.2 各工作区列表

| 工作区 | 左侧栏下方内容 | 主内容区 |
|---|---|---|
| 素材库 | 搜索、状态/来源筛选、素材列表 | 素材详情；无选择时显示录音与导入动作 |
| 处理任务 | 运行中、等待授权、失败、已完成任务 | 任务概览、阶段、错误与重试入口 |
| 文字转音频 | 最近输入/导出记录；首版无历史时显示简短说明 | 现有文字/文件转音频界面 |
| 设置 | 录音与输入、模型与转写、文件与隐私 | 现有分区设置表单 |

现有 Agent Job 可以继续作为“处理任务”列表中的一种任务状态，但点击后仍进入现有任务/结果路径，不形成聊天界面。

### 4.3 素材列表行

- 第一行：素材标题，最多两行；右侧为不可换行的状态图标。
- 第二行：日期 · 时长 · 来源，使用单行次要文字；来源以图标 + 文字区分“录制”“导入音频”“导入视频”。
- 失败或部分就绪使用图标 + 短标签；颜色只作辅助，不作为唯一状态信号。
- “素材已就绪”缩短为“就绪”；完整说明放入可访问标签或详情。
- 列表支持完整键盘选择、上下移动、Enter 打开和 VoiceOver 朗读。

### 4.4 空状态与工具栏

- 素材库无数据：同时显示“开始录音”主动作和“导入音视频…”次级动作，并保留录音快捷键提示。
- 有数据但未选择：显示最近一条素材摘要、“打开最近素材”“开始录音”和“导入音视频…”。
- 搜索无结果：显示当前查询条件、清除筛选动作，不显示泛化空白页。
- 处理任务为空：明确说明没有待处理任务，不制造错误感。
- 素材库和素材详情的窗口工具栏持续显示 `[导入音视频…] [开始录音]`；设置、处理任务和文字转音频页不显示导入入口。
- “开始录音”保持强调按钮；“导入音视频…”使用 `square.and.arrow.down` 次级按钮，不放入省略号菜单，也不做成录音按钮下拉项。
- 工具栏图标必须同时具备可理解的 Label、Help 和 VoiceOver 名称；仅图标按钮不得依赖用户猜测。

### 4.5 音视频导入与转写连续流程

目标路径：

```text
选择文件 -> 导入/准备完成 -> 立即转文字 -> 转写完成 -> 素材库选中新素材并显示详情
```

- 菜单栏在录音主动作下提供较轻的“导入音视频…”；点击后打开工作台并直接弹出与工具栏共用的文件选择器。
- 文件选择后使用同一个窗口级 Sheet 展示导入、准备、待转写、转写中、失败和完成状态，不新增一级工作区或独立窗口。
- 导入完成后立即显示唯一主动作“转文字”；本机模型直接进入现有 ASR，外部服务显示“确认并发送转写”，未选择模型时显示模型设置入口。
- 转写成功后关闭 Sheet，通过现有素材路由进入素材库、选中刚完成的素材，右侧直接展示原文。
- 转写失败时 Sheet 不关闭；明确说明文件已安全保存，提供“重新转写”和“稍后处理”，不得要求用户重新导入。
- 用户主动选择“稍后处理”后，未转写素材保留在素材库并显示真实状态；该路径不得自动外发。

### 4.6 文件、来源与复用边界

- 首版接受 WAV、MP3、M4A、AAC、AIFF、CAF、FLAC、MP4、MOV 和 M4V；必须以实际解码与音轨探测为准，不能只校验扩展名。
- 导入文件立即复制到 Woice 受控目录；原音频或视频作为不可变原件保存，提取/标准化音频作为派生文件，重转写前后原件 SHA-256 不变。
- 视频没有音轨、文件损坏、受保护或系统无法解码时响亮失败，不创建“已完成”素材。
- 领域层只给现有 `RecordingRecord` 增加录制/导入来源和原文件元数据；旧记录缺少来源字段时兼容为“录制”，不创建第二套 Material/Recording 模型。
- 导入后的转写继续复用现有 ProcessingTask、Lease、Provider 选择、外发确认、Transcript Artifact 版本链、搜索、复听、导出、Markdown 和 Agent 路径。
- 长文件按实际 Provider 能力受控分段并合并时间戳；分段任务必须可恢复，不把单次 HTTP 上传限制暴露成无解释失败。

## 5. 权限连续性设计

### 5.1 权限语义

| 能力 | 系统权限 | 默认策略 |
|---|---|---|
| 麦克风录音 | 麦克风 | 用户点击录音时按需请求 |
| 电脑声音 | 屏幕与系统音频录制 | 会议模式开启后按需请求；说明不保存屏幕画面 |
| macOS Speech 回退 | 语音识别 | 仅选择该能力时请求 |
| 复制原文 | 无辅助功能权限 | 默认可用 |
| 自动粘贴到当前应用 | 辅助功能 | 默认关闭，用户显式开启时请求 |

### 5.2 稳定代码身份

当前 ad hoc 包只用于本机运行，不作为权限继承验收对象。启动本计划后按发行渠道验证：

- 开发验证：固定 Apple Development Team、Bundle ID、可执行文件名和 Entitlements。
- 官网发行：复用 M1-07/M2-08i 的固定 Developer ID Application 身份、Hardened Runtime 和公证结果。
- Mac App Store：复用上架计划的固定 App Store 签名和 Bundle ID，在 TestFlight/Store 身份下单独验收。
- Core/Offline 不作为两个可并存应用安装；同一渠道保持相同产品身份和数据迁移规则。
- 覆盖安装只改变版本号和 Build Number，不修改 Bundle ID、Team ID 或关键权限 Entitlements。

### 5.3 ad hoc 到稳定签名的一次迁移

- 首次稳定签名版本显示一次迁移说明，不宣称旧 ad hoc 授权一定可继承。
- 系统仍保留旧 Woice 授权但当前实例不可用时，提示移除旧项并授权当前安装包。
- 麦克风、系统声音、语音识别和辅助功能逐项恢复，不提供“一键索取全部权限”。
- 授权完成后引导用户关闭并重新打开 Woice；回到 App 后刷新运行时能力状态。
- 不自动调用 `tccutil reset`；任何权限重置必须由用户明确触发并说明影响范围。

## 8. 实施时计划新增门禁

以下专项命令已加入代码门禁；默认只验证代码契约，不伪造真实桌面、TCC 或稳定签名结果：

```bash
make acceptance-workspace-sidebar
make acceptance-media-import-transcription
make acceptance-media-import-desktop
make acceptance-permission-continuity
make acceptance-stable-upgrade
make acceptance-launch-window
make acceptance-accessibility-runtime
# 可选：真实工作区快捷键 Journey
WOICE_RUN_KEYBOARD_JOURNEY=1 WOICE_RUN_ACCESSIBILITY_JOURNEY=1 make acceptance-accessibility-runtime
```

当前代码侧可执行：acceptance-workspace-sidebar、acceptance-media-import-transcription、acceptance-media-import-desktop、acceptance-permission-continuity、acceptance-accessibility-runtime；WOICE_RUN_LAUNCH_JOURNEY=1 make acceptance-launch-window 已在稳定签名 Build A 的 /Applications/Woice.app 实测通过启动、关闭、open -a 重开和单实例；WOICE_RUN_ACCESSIBILITY_JOURNEY=1 make acceptance-accessibility-runtime 已通过侧栏 AX 树检查，WOICE_RUN_KEYBOARD_JOURNEY=1 同时运行时已通过先回到素材库再用 ⌘2 切换处理任务；真实文件面板和录音按本轮用户要求保留手动路径，不将脚本自动点击计为通过；acceptance-stable-upgrade 现在生成并比较 A/B，只有设置 WOICE_RUN_STABLE_UPGRADE=1 且提供稳定身份后才执行，显式运行遇到 adhoc/无 Team ID 会失败关闭，并把旧安装包与签名证据保留在输出目录。

用户手动验收的逐步路径、截图要求和结果回传格式见[当前版本手动验收运行手册](../../specs/2026-08-23-manual-acceptance-runbook.md)。本轮真实录音、真实文件导入、真实会议声源和真实第三方 Provider 不由 Codex 自动执行。

专项门禁至少检查：

- 一级导航与上下文列表只有一个侧栏可访问容器。
- 280/320/360 pt 侧栏宽度和最小窗口截图。
- 音频/视频导入、无音轨/损坏文件、长文件分段、转写成功自动选中和失败恢复。
- 键盘、VoiceOver、浅色、深色和高对比状态。
- Build A/B 的 Bundle ID、Team ID、Designated Requirement 和 Entitlements 一致性。
- 麦克风、系统声音、语音识别和辅助功能的真实覆盖安装结果。
- 复制不依赖辅助功能；自动粘贴 fail-safe。
- 原始 Artifact SHA-256 不变。

## 9. 风险与处理

| 风险 | 等级 | 处理 |
|---|---:|---|
| 素材行继续因状态文案过长而拥挤 | P1 | 状态缩写 + 可访问完整说明；固定右侧图标，不允许纵向断词 |
| 布局重构影响设置草稿或列表选择 | P0 | 路由与业务状态不迁移，只替换 UI 容器；增加切换回归 |
| 导入完成后跳回列表造成流程断裂 | P0 | 同一 Sheet 保持到转写结束；成功后自动选中新素材，失败原位重试 |
| 视频只有画面或格式扩展名可选但实际不可解码 | P1 | 以真实音轨探测和解码为准；无音轨/受保护/损坏文件响亮失败 |
| 长文件超过外部 Provider 单次上传限制 | P1 | 发送前按能力分段、持久化任务并合并时间戳；不静默截断或无限重试 |
| 导入逻辑复制现有转写体系 | P0 | WPC-04 只新增摄取与来源边界；ASR、任务、版本、导出和 Agent 全部复用 |
| 把 CLI 任务误改成聊天入口 | P0 | AC-WPC-005/006 fail-closed；M2-09 仍是唯一 Agent 计划 |
| ad hoc 包被误用于权限继承验收 | P0 | 门禁要求 Team ID 与稳定 Designated Requirement；ad hoc 直接失败 |
| Developer ID 与 Store 身份被误认为共享授权 | P1 | 按发行渠道分别记录和验收，不承诺跨渠道继承 |
| 用户误以为复制也需要辅助功能 | P1 | 复制默认可用；自动粘贴单独开关和用途说明 |
