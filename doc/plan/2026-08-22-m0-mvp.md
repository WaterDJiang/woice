## 1. 计划目标

产品优先级固定为：录音可靠性 -> 转写与模型 -> 素材管理 -> Agent 协作。Woice 不是 AI 网关；Agent 只在素材完成后承担通用后续处理，或在授权范围内读取 Woice 上下文。

当前有效路线为：

```text
录音与素材核心收口
  -> M2-08 ASR、模型与 Core/Offline
  -> 素材库收口
  -> M2-09 Agent 协作
```

开发成功不是“界面能录音”，而是同时满足：

- 用户能明确知道是否在录音、数据在哪里处理、失败后怎么恢复。
- 原始音频和原始转录不会被 LLM 或编辑覆盖。
- 录音后的任务可在崩溃、重启后恢复。
- 内置模型可通过配置切换；外部模型不侵入 Runtime。
- Agent 默认不能静默启动麦克风。
- 每个阶段都有可执行命令、固定样本和验收记录。

## 3. 交付边界

### 核心发布必须交付（由当前迁移表裁决阶段）

- 菜单栏常驻与开机启动。
- 标准组合键快捷键。
- 麦克风录音、取消、异常恢复。
- 原始音频与原始转录不可变保存。
- 可用 ASR 与原始转录；WhisperKit、模型下载和断网转录由 M2-08 交付。
- 历史、搜索、详情、Markdown 导出。
- ASR/Profile 配置和 Keychain 密钥。
- 签名、Notarization、升级兼容和隐私验证。

本地 JSON-RPC 的现有基础可保留，但 stdio MCP Bridge 与外部 Agent 工具不再是无 Agent 核心发布门槛，统一迁入 M2-09e。

### M1 明确不交付

- 系统音频、双音轨和说话人分离。
- Fn/Globe 等 Event Tap 快捷键。
- 自动粘贴、PI Extension、TTS。
- 任意第三方动态库或插件市场。
- 无人确认的自动会议录音。
- 账号、云同步、团队协作。

### 4.3 依赖门禁

- 新依赖必须说明：解决的问题、为何系统框架/现有依赖不能完成、许可证、版本、替代方案。
- 默认只接受 MIT；Apache-2.0、BSD 等必须先新增 ADR 并获得明确确认。
- 依赖使用精确版本或受控 minor range，并提交 `Package.resolved`。
- 模型权重、Tokenizer、词表和下载资产按独立产品登记许可证。
- 不使用 GPL/AGPL 项目代码、资源或构建产物。
- 参考项目声明不能替代 Woice 自己的运行测试。

## 5. 组件化设计

### 5.1 立场

**先定边界，再写实现；用组合吸收变化，不把“可替换”误解成“所有东西都是插件”。**

M1 是模块化单体：一个签名 App 承担菜单栏、权限和 Runtime 生命周期。第三方模型走受控进程；Agent 走本地 RPC。M0 没有证据前，不拆 Daemon、不做插件市场。

### 5.2 计划目录

```text
woice/
├── project.yml                    # XcodeGen 工程事实源
├── Makefile                       # 统一命令入口
├── App/
│   └── WoiceApp/                  # App、Entitlements、Info.plist、组合根
├── Sources/
│   ├── WoiceDomain/               # ID、实体、Artifact、错误、Provider 契约
│   ├── WoiceRuntime/              # 状态机、Pipeline、Job、Policy、恢复
│   ├── WoiceAudio/                # 设备、录音、分段、音频格式
│   ├── WoiceStorage/              # GRDB、迁移、FTS、文件 Artifact
│   ├── WoiceProviders/            # WhisperKit、LLM、导出内置 Provider
│   ├── WoiceRPC/                  # 本地 JSON-RPC Server/Client/Schema
│   └── WoiceUI/                   # 共享 View、ViewModel、Design Token
├── Connectors/
│   ├── WoiceMCP/                  # stdio MCP -> WoiceRPC
│   └── PiWoice/                   # P2，独立 TypeScript 包
├── Tests/
│   ├── Unit/
│   ├── Integration/
│   ├── Contract/
│   ├── UI/
│   └── Fixtures/                  # 固定音频、转录、RPC、迁移样本
└── doc/                           # spec -> plan -> log
```

### 5.3 依赖方向

```text
WoiceDomain
  ↑      ↑       ↑        ↑
Audio  Storage  Providers  RPC
  \      |       /        /
       WoiceRuntime
            ↑
         WoiceUI
            ↑
         WoiceApp

WoiceMCP -> WoiceRPC Client
PiWoice  -> WoiceRPC Client
```

强制规则：

- `WoiceDomain` 不依赖 UI、数据库、网络、音频和具体模型。
- `WoiceRuntime` 只依赖 Domain 中的端口协议，不 import 具体 Provider。
- `WoiceStorage` 不决定业务状态迁移；事务能力由 Runtime 用明确接口调用。
- `WoiceUI` 不直接操作数据库、文件、AVAudioEngine 或 URLSession。
- `WoiceApp` 是唯一组合根；具体 Provider 只在这里注册。
- Connector 不读 SQLite、不访问音频设备，只调用 `WoiceRPC`。
- 跨模块共享必须是领域概念；通用工具不足以单建 `Utils` 模块。

### 5.4 模块职责

#### WoiceDomain

- `RecordingID`、`ArtifactID`、`TaskID` 强类型 ID。
- `Recording`、`Artifact`、`Transcript`、`Job`、`Profile`。
- `AudioSource`、`ASRProvider`、`LLMProvider`、`TTSProvider`、`ExportProvider` 契约。
- 稳定错误码和可重试分类。

不包含：SQL、文件路径拼接、HTTP、SwiftUI、模型 SDK 类型。

#### WoiceRuntime

- 录音与处理状态机。
- 任务调度、Lease、幂等键、取消和恢复。
- Pipeline 配置解析和 Provider 路由。
- 录音、云端外发、Agent 访问策略。
- 持久事件与读模型协调。

所有跨任务可变状态由 Actor 持有；禁止用全局单例共享 Runtime 状态。

#### WoiceAudio

- 输入设备枚举和切换。
- 电平、格式转换、分段录音和中断处理。
- 每段固化后返回 Artifact 草案，不直接写业务表。
- M2 增加 ScreenCaptureKit 与双音轨对齐。

#### WoiceStorage

- SQLite 迁移、WAL、FTS5、备份与恢复。
- Recording、Artifact、Event、Job、Connector Audit 表。
- Artifact 文件原子落盘、SHA-256、可恢复删除。
- 不实现通用 `StorageProvider`；M1 保持单一事务真相源。

#### WoiceProviders

- `WhisperKitASRProvider`。
- `OpenAICompatibleLLMProvider` 与 `Ollama` 配置预设。
- `MarkdownExportProvider`。
- P2 进程 Provider Host。

每个 Provider 负责把 SDK 类型转换为 Domain 类型；SDK 类型不得穿透边界。

#### WoiceRPC

- JSON-RPC v1 Schema、Codec、Unix Socket Server/Client。
- 请求大小、分页、超时、调用方标识和审计上下文。
- 长操作返回 `taskId`；不持有业务状态。

### 5.5 抽离规则

命中任一才抽，不为“未来可能”建层：

- 同一领域校验出现 2 次：下沉 Domain/Runtime。
- 同一数据访问模式出现 2 次：进入 Storage 查询对象。
- 同一 SwiftUI 区块出现 2 次：抽 View。
- 同一状态副作用被 2 个 ViewModel 使用：抽 Runtime 用例。
- View 超过 250 行、ViewModel 超过 300 行、函数超过 60 行或参数超过 5 个：拆分或引入请求结构体。
- 一个类型有两个独立变更原因：按职责拆分。
- 仅为了少写 5 行而产生的新协议：不抽。

### 5.6 Provider 运行形态

| 形态 | 使用场景 | 规则 |
|---|---|---|
| 内置 Swift Provider | 系统能力、WhisperKit、GRDB、导出 | 随 App 编译和签名 |
| 受控进程 Provider | Python/Node/Rust 模型 | stdio JSON-RPC、环境白名单、超时、输出上限 |
| Agent Connector | MCP、PI、DSH | 只调用本地 RPC，不进入 Runtime 进程 |

禁止：运行时下载并 `dlopen` 任意 `.dylib` 或 Swift `.bundle`。

## 6. 数据与状态设计

### 6.1 不可变链

```text
AudioArtifact(raw)
  -> TranscriptArtifact(raw)
      -> TextArtifact(corrected)
      -> TextArtifact(edited)
      -> TextArtifact(summary)
      -> JsonArtifact(action_items)
```

- 原始 Artifact 创建后只允许追加元数据，不允许改内容。
- 人工编辑和重新转录都创建新 Artifact。
- 每个 Artifact 保存 `parentID`、`supersedesID`、Provider、模型、配置快照和 SHA-256。
- UI 默认展示“当前推荐版本”，但必须能回到原始版本。

### 6.2 录音持久化

- 工作格式优先使用易恢复的线性 PCM 容器；最终格式由 M0-03 Spike 冻结。
- 每 30 秒形成一个已关闭分段；分段时长必须可配置用于测试。
- 分段先写 `.partial`，完成校验后原子重命名。
- 停止后生成清单；后续转码不得删除原始分段，直到完整性验证通过。
- 强退 App 后最多丢失当前未关闭分段。

### 6.3 Job 与 Event

- Job 状态：`queued -> running -> completed | failed | cancelled | interrupted`。
- `running` 使用 Lease；App 重启将过期 Lease 转为 `interrupted`。
- 同一输入、Provider、配置快照生成稳定幂等键。
- 自动重试仅处理明确可重试错误；用户取消、Schema 错误、权限拒绝不重试。
- 状态变化先追加 Event，再更新查询投影；失败不得伪装为完成。

## 7. UI 设计原则

### 7.1 设计方向

**Quiet Native Utility：安静、原生、状态明确。**

Woice 是长期常驻工具，不做高饱和 AI 仪表盘，不使用自定义标题栏或网页式卡片堆叠。默认沿用 macOS 系统材质、系统字体、SF Symbols 和语义色。

### 7.2 Design Tokens

| Token | 值 | 用途 |
|---|---|---|
| `space-1` | 4 pt | 图标与短标签 |
| `space-2` | 8 pt | 控件内部间距 |
| `space-3` | 12 pt | 相邻字段 |
| `space-4` | 16 pt | 区块边距 |
| `space-6` | 24 pt | 大区块分隔 |
| `radius-control` | 系统默认 | 按钮、输入框 |
| `radius-panel` | 10 pt | 非系统容器 |
| `status-recording` | `Color.red` 语义色 | 只用于正在录音与破坏性删除 |
| `status-processing` | `Color.orange` 语义色 | 转录/处理 |
| `status-success` | `Color.green` 语义色 | 完成；不大面积铺色 |
| `status-failed` | `Color.red` + 图标/文字 | 错误，不只靠颜色 |

规则：

- 所有尺寸以 4 pt 网格为基线。
- 字体使用系统 Text Style；计时器用 monospaced digits。
- 图标只用 SF Symbols；同一层级统一 16/18/20 pt。
- 支持浅色、深色、高对比和减少动态效果。
- 状态始终由“颜色 + 图标 + 文字”共同表达。
- 动画 120-200 ms；录音开始不得使用延迟或花哨入场。

### 7.3 信息架构

#### 菜单栏 Popover

默认宽 336 pt，只承载：

1. 当前状态：待机、正在录音、正在转录、失败。
2. 主动作：开始/停止；录音时优先显示计时和输入电平。
3. 当前 Profile 与处理位置：本机或具体云端 Provider。
4. 最近一条结果：标题、前两行、复制/打开。
5. 入口：历史、设置、退出。

Popover 不放完整历史列表、复杂模型表单或调试日志。

#### 历史窗口

- 最小尺寸 800 x 560 pt。
- Sidebar：全部、最近、收藏、失败、标签。
- List：标题、时间、时长、来源、状态。
- Detail：音频播放器、原始转录、当前版本、摘要、待办、Artifact 版本。
- 原始转录使用不可编辑样式；“编辑”明确创建派生版本。

#### 设置窗口

固定分组：

- 通用：开机启动、快捷键、默认 Profile。
- 录音：输入设备、格式、分段、声音提示。
- 模型与转写：ASR、模型下载和连通性测试；旧 LLM 配置只作兼容。
- Agent 与连接：只在 M2-09 实施，不进入录音首次启动主流程。
- Profiles：Pipeline 组合与默认输出。
- 隐私与连接器：云端授权、MCP、Agent 权限、审计。
- 存储与诊断：位置、用量、保留期、导出诊断。

#### 首次启动

只分三步：

1. 产品承诺：本地优先，录音不会静默开始。
2. 麦克风权限：解释用途，点击后才触发系统弹窗。
3. 本地模型：显示大小、语言和预计下载；允许稍后下载。

开机启动、Accessibility、Input Monitoring、系统音频权限不在首次启动一口气索取。

## 8. UX 原则：D-S-T-E

### 8.1 Diagnose：先诊断用户卡点

每个里程碑至少做一次盲测，观察而不指导。记录三类“3 秒停顿点”：

- 用户不确定是否已经开始录音。
- 用户不确定声音是在本机还是云端处理。
- 用户不确定处理中能否关闭窗口或退出 App。

任一点让 2 名测试者停顿超过 3 秒，该流程不得通过 UX 验收。

必须埋点到本地诊断日志的产品事件：权限拒绝、录音启动失败、任务失败、用户取消、模型下载失败。默认不记录语音内容。

### 8.2 Simplify：核心操作不超过三步

- 开始/停止录音：一个快捷键或一个主按钮。
- 打开最近结果并复制：不超过 2 次操作。
- 从录音到看到原始转录：无需填写表单。
- 完整设置 Profile：不超过 5 个主步骤；高级参数折叠。
- 能从系统获取的输入设备、语言和保存位置不让用户手填。
- 权限按功能渐进请求，不做“权限大全”页面阻断首次使用。

### 8.3 Translate：用用户语言解释系统

文案规则：

- 写“正在本机转录”，不写“ASR Pipeline running”。
- 写“将把这段文字发送给 Codex 处理”，不写“调用 Remote Provider”。
- 写“没有检测到声音，请检查输入设备”，不只显示错误码。
- 错误必须包含：发生了什么、数据是否安全、下一步按钮。
- 原始转录、AI 修订、人工编辑必须有明确标签。
- 内部错误码可复制到诊断信息，但不作为主文案。

示例：

```text
转录没有完成
录音已安全保存在这台 Mac 上。
[重新转录] [更换模型] [打开录音]
```

### 8.4 Emotify：用确定性降低焦虑

- 快捷键触发后 300 ms 内给出菜单栏与声音/视觉反馈。
- 处理超过 3 秒显示阶段；能估算时显示预计剩余时间，不能估算时说明当前工作。
- 模型下载显示大小、已下载、可暂停/重试。
- 成功反馈克制：状态切换和轻提示即可，不使用庆祝动画。
- 失败先说明“原始录音是否安全”，再提供动作。
- AI 输出旁持续显示来源模型和生成时间，避免把生成内容伪装成原文。

### 8.5 无障碍与隐私体验

- 所有图标按钮有 VoiceOver Label 和 Tooltip。
- 全流程可键盘操作；焦点顺序与视觉顺序一致。
- 动态电平表在 Reduce Motion 下改为低频更新。
- 不用颜色作为唯一状态信号；对比度遵循系统高对比设置。
- 正在录音时菜单栏图标、Popover 和历史窗口都显示一致状态。
- 外部 Agent 请求录音时，默认返回 `USER_GESTURE_REQUIRED`，而不是弹出隐藏确认框。
