## Qwen 转写会议音频崩溃诊断（只读调查）

- 范围：用户指定的 1136.9 秒 meeting-mix.m4a；不修改产品代码、用户音频、数据库或安装包。
- 依据：`specs/2026-09-07-meeting-single-pass-transcription.md`；当前 `Qwen3ASRService.swift` 与锁定 Qwen/MLX 依赖源码。
- 系统日志：09:33:25、09:34:34、09:35:55、09:40:14、09:41:44 均为 `MLX/ErrorHandler.swift:345: Fatal error: [stack] No arrays provided for stacking`。Dev 0.1.6 (11) 和 Store 0.1.7 (12) 堆栈一致：Qwen3AudioEncoder → mlx_stack_axis → ErrorHandler → SIGTRAP。
- `afinfo`：原 M4A 为 48 kHz 单声道 AAC，1136.9 秒；崩溃残留标准化 WAV 为 16 kHz Float32，18,190,400 帧。
- 真实 AVAudioFile 只读探针：每次请求 480,000 帧，前 37 次实际返回 479,232 帧；第 38 次返回 458,752 帧；第 39 次返回 64 帧（4 ms）。最后一段峰值 0.04438386，高于现有过滤阈值 0.01，因此进入模型。
- 根因链：当前循环把每次短读直接当作完整分段；最后 64 帧经 Qwen hopLength=160 的特征提取后为零时间帧；AudioEncoder 无空特征防护，调用 stacked([])；默认 MLX fatalError 不能被现有 Swift do/catch 捕获，导致 App 退出。
- 验证命令：`afinfo <用户指定 M4A>`、`afinfo <崩溃残留 WAV>`、`swift -module-cache-path /private/tmp/woice-probe-module-cache /private/tmp/woice-read-probe.swift <崩溃残留 WAV>`、`/usr/bin/log show --start '2026-09-22 09:32:00' --end '2026-09-22 09:42:00' --predicate 'process == "Woice" AND (eventMessage CONTAINS "stack" OR eventMessage CONTAINS "Fatal" OR eventMessage CONTAINS "shape")' --style compact`。
- 调查异常：IPS 最后一份有附加 System Profile，json.loads 报 Extra data，改用 raw_decode 成功；log show 沙箱拒绝后经只读提权成功；Swift 默认缓存目录不可写，改用 /private/tmp 缓存成功。两次依赖文件路径探查返回 No such file，随后通过 rg 定位实际 AudioPreprocessing.swift。
- 后续修复方向（尚未实施）：累积短读至目标分段大小、合并或补齐不足一个特征步长的尾段，并建立模型错误隔离；先补边界失败复现和有效 Spec，再验证真实音频链路。不要用扩大静音阈值丢弃有效尾音。
