# 录音侧栏全生命周期可见性

## 目标与范围

用户开始录音时，恢复 Journal 成功落盘后即在素材库顶部建立同 ID 的会话记录。覆盖准备、录音、停止保存与后台分段转写等待；正式 Recording 提交后原位接续现有任务状态。仅调整 AppState 与工作台投影，不改音频、ASR、数据库 Schema 或外发规则。

## 行为与验收

- 会话行以持久化 Journal 为依据；未提交正式 Recording 时不伪称“已保存”。显示准备录音、正在录音、正在保存并整理转写；图标和文字同时可见。
- 录音行不受搜索/历史状态筛选隐藏；小素材库与 250 条以上摘要列表行为一致。提交后同 ID 只出现一次，创建时间沿用会话开始时间。
- 选中会话可查看状态；正式记录提交后同一选择自动展示详情。不抢走旧素材选择。会话完成前禁用删除/重命名。
- 停止操作进入等待前标记保存中，禁止并发停止和开始新录音。失败保留准确错误；恢复文件存在不等于已成功保存素材。
- 启动失败清理空会话行；保存失败保留错误行与现有恢复 Journal。成功后复用已持久化任务的就绪/失败/等待模型/等待授权状态。
- 空列表有会话时不显示“还没有素材”。保持当前 1080×700 最小窗口与侧栏宽度，文字允许换行；键盘选择/VoiceOver 可读，不增加动画。

## 验证与影响面

自动测试覆盖会话行出现、录音/保存/失败状态和提交去重；构建、格式、文档门禁验证。真实 Mac 手工验收：开始后立即看到行；结束后慢转写期间行持续可见；点击会话再等完成，原位进入详情；切换历史选择不被抢走；明暗、窄窗、键盘及 VoiceOver 检查。未执行的设备门禁单独记录。

兼容：复用 RecordingSessionJournal 与原恢复流程，不将未完成音频写成正式素材；旧记录无迁移，新旧原件不修改。保留现有未提交改动和 REC/ECHO 等其他计划范围。
