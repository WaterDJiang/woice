# 后台分段转写耐久化规格

> 状态：代码与自动门禁完成；真实长会、睡眠和崩溃恢复 Journey 待验收
> 日期：2026-08-23
> 替代：无；补齐 R0 的 M2-02/M2-03 本机后台分段转写缺口
> 保留：原始 WAV 是不可变真相源，后台片段只是可重建的派生输入
> 迁移：录音会话 Journal 继续负责会话恢复；后台结果另存为同一录音 ID 的 sidecar
> 停止：不把后台片段结果写回正在录音的原始 WAV，不把失败片段静默标记为成功
> 顺序：录音分段固化 -> sidecar 原子更新 -> 录音停止时合并 -> 成功提交后清理

## 目标

- 长时间录音期间，本机模型可以串行处理已经关闭的声音片段。
- 每个已完成片段在处理完成后立即写入本地 sidecar；应用异常退出后仍可恢复已完成结果。
- 录音停止时优先使用已持久化结果，未完成或失败的片段继续走完整录音转写/人工重试路径。

## 数据与边界

- sidecar 路径固定为 `recordings/<recording-id>.background.json`，不接受 UI 或外部输入路径。
- sidecar 只包含片段索引、`TranscriptSegment` 结果、失败索引和更新时间，不包含 API Key、完整音频或模型权重。
- 写入采用临时文件 + 原子替换；写失败不影响原始录音和当前内存结果。
- 恢复时只读取与有效 `RecordingSessionJournal.id` 相同的 sidecar，并校验片段索引非负、时间戳非负且文本非空。
- 录音成功提交为 `RecordingRecord` 后，清理 sidecar；会话恢复生成的记录保留可恢复结果，并把未完成部分明确标记为待转写/部分就绪。
- 原始 WAV、系统音频和已有 Transcript Artifact 不原位修改；后台结果仅作为新提交的 Transcript 字段来源。

## 验收标准

- `make test` 覆盖：原子写入/读取、损坏 sidecar fail-closed、重启恢复已完成片段、成功提交后清理。
- 恢复后原始音频 SHA-256 与退出前相同。
- 后台结果不完整时不得显示“素材已就绪”；失败片段必须保留可重试状态。
- 不配置本机 ASR 或未获授权时不创建 sidecar。
- `make verify`、`make docs-check`、`make harness-check` 通过。
