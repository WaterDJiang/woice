# 系统音频窗口级回退规格

> 状态：代码与 QuickTime 可见声源门禁完成；全桌面、多窗口、真实会议应用和当前包 TCC Journey 待验收
> 日期：2026-08-23
> 范围：M2-01 系统音频采集与 M2-08 会议录音验收

## 背景

ScreenCaptureKit 的全桌面采集需要一个可共享显示器。锁屏、远程桌面或无物理显示器环境中，权限可能已经允许，但运行时仍返回空的 `displays`，导致会议模式无法开始系统音频轨道。

## 目标

- 有可共享显示器时保持现有语义：采集整个桌面输出，覆盖视频、会议和其他系统声音。
- 没有显示器但存在可捕获窗口时，允许用户继续录音并仅采集活动应用窗口的输出。
- UI 必须明确“窗口级回退”与“全桌面采集”的差异，不把窗口级结果标记为全系统声音。
- 没有可用显示器或窗口时继续 fail-closed，并保留麦克风录音。
- 不新增虚拟声卡、动态库或云端回退；不改变屏幕录制权限边界。

## 非目标

- 不自动选择任意后台窗口或跨应用拼接多个窗口。
- 不绕过 macOS 屏幕录制权限。
- 不承诺受保护媒体、锁屏和远程桌面下的全系统声音采集。

## 验收标准

- AC-WF-01：显示器数量大于 0 时，选择 display filter，能力状态为“系统音频能力可用”。
- AC-WF-02：显示器为 0、存在非 Woice 活动/可见窗口时，选择 window filter，能力状态明确为“仅窗口级系统音频可用”。
- AC-WF-03：无显示器且无可捕获窗口时，返回“没有可用的系统音频采集目标”，不创建采集文件。
- AC-WF-04：窗口级回退的录音详情明确标记“活动窗口音频”，不能写成“已获取系统输出”。
- AC-WF-05：现有权限拒绝、停止、写入错误、麦克风保留和原始音频不可变测试继续通过。
- AC-WF-06：`make test`、`make docs-check`、`make lint` 通过；真实桌面全系统声音仍需在有显示器环境单独验收。

## 设计决策

- 采集目标决策属于 SystemAudioCaptureService 与 SystemAudioCapabilityService 的共享确定性策略，不引入新的 Domain 实体。
- 目标优先级固定为：display > active non-Woice window > on-screen non-Woice window。
- 窗口级回退只在 `displays.isEmpty` 时启用；正常桌面不改变当前全桌面采集行为。
