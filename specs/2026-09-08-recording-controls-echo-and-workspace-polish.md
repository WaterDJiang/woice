## 1. 目标、证据与边界

- 主界面开始录音后，在同一窗口一键结束并保存；切换素材、任务或收起侧栏后仍能停止。
- 区分双轨任务重复、声学回声与模型重复，减少外放会议重复且保护本地说话内容。
- 延续 Quiet Native Utility，改善信息密度、状态层级、留白和可访问性。
- 保留双原件、单次会议转写、历史版本、独立 CLI 协作和现有数据安全约束；不增加 AI 对话、暂停录音或新模型。

本轮证据是用户提供的 `codex-clipboard-db513ea0-2a1f-47d3-96d4-c04336d081cc.png` 和当前源码。没有访问用户音频、复现真实会议或执行完整 UI Journey；截图像素不直接等于 SwiftUI 的 pt。

| 发现 | 证据 | 结论与限制 |
|---|---|---|
| 实时文字显示“正在听”，主体仍显示“选择一条录音”和开始按钮 | 用户截图；`WorkspaceView.swift` 的 `WorkspaceLibraryEmptyState` 只有 start 回调 | 录音控制没有贯穿主体状态，静态开始按钮需替换 |
| 预览与主体割裂 | `WorkspaceView` 顶部 ZStack 叠加预览 | 需要占据布局空间的会话区域，不能遮盖详情与反馈 |
| 外放重复 | `AudioPreparationService.mix` 双轨固定 gain 0.5 相加，无 AEC；当前默认 `standardMix` | 混音可包含直接电脑声音及其延迟回声；尚不能凭截图认定本次实例唯一根因 |
| 列表大片灰底、每行反复显示绿色就绪、标题拥挤 | 用户截图 | 减少重复状态；灰底的实际来源需在活动/非活动窗口、明暗主题核对 |
| 小窗适配不一致 | 当前 Workspace 最小 1080×700，Harness 基线为 800×560 | 本次定义并验证紧凑布局，不直接按截图缩放字号 |

实施前用固定无隐私样本核对任务次数、激活 Transcript、混音复听及两原轨的时序；记录当前 Channel、二进制指纹和策略，版本 `0.1.4 (9)` 本身不能唯一识别修复包。长音频按 chunk 调用 Provider 是正常行为；检查“单条音频时间线”，不能把所有情况硬断言为一次底层调用。

## 2. 录音交互契约

在工作台内容列顶部增加会话控制区，所有工作区可见。空闲时为紧凑的“录音来源 · 开始录音”；录音时展示红色状态点、文字、等宽时长、实际来源和“结束并保存”。菜单栏和工作台共享 AppState 的会话状态及命令，不各自持有录音布尔值或计时真相源。

| 状态 | 主动作和文案 | 行为 |
|---|---|---|
| 空闲 | 开始录音 | 来源可调整；双关禁用并说明原因；首次权限沿用现有流程 |
| 正在启动/等待权限 | 正在准备录音… | 立即反馈，禁重复开始；准备失败可重试，未真正采集不显示计时 |
| 正在录音 | 结束并保存 | 一个明确 stop 图标按钮；点击立即变为正在保存；不弹结束确认 |
| 正在停止/保存 | 正在保存录音… | start/stop 均禁止重复提交；跨窗口并发停止合并为一次 |
| 已保存、正在转写 | 录音已保存 · 正在转写 | 后台任务独立显示；是否可再次录音遵循现有运行时能力 |
| 保存失败/中断 | 说明已保存部分、失败与恢复动作 | 无提交证据不得显示“已保存”；复用既有恢复路径 |

- 原“选择一条录音”空状态在录音期间改为当前会话视图，移除静态开始按钮。查看旧素材时保留详情及选中项，会话区持续显示停止入口。
- 实时文字放在会话区下方的可折叠区域；关闭实时文字、权限失败或只录电脑声音时，停止按钮仍可用。标注“实时预览，以最终转写为准”，按当前能力说明预览来源。
- 主窗口重新打开时从当前会话恢复；关闭窗口不停止录音，并保留菜单栏可见录音状态。
- 常规按钮反馈 ≤300 ms；超过 3 秒显示阶段。保存时间不承诺固定小于 300 ms。
- 结束操作不新增未经实现的暂停/丢弃按钮。键盘使用现有快捷键映射，Escape 不结束录音。

## 3. 外放重复：产品策略

电脑声音直接进入系统轨，同时经扬声器、房间反射、麦克风再次进入麦克风轨。固定混音并不消除这条延迟路径；只做文本去重可能删掉真实复述或打断时的话。

| 使用场景 | 来源选择 | 行为 |
|---|---|---|
| 只记自己的口述/线下谈话 | 麦克风 | 保留现有单轨路径 |
| 只保存电脑课程/视频 | 电脑声音 | 关闭麦克风可避免本地回采；必须由用户选择 |
| 戴耳机参加线上会议 | 双开 | 保留标准会议合成与单次转写 |
| 外放参加线上会议且需要自己的发言 | 双开 | 回声处理达标后提供“减少外放回声”；未达标先提示耳机方案 |

录音前显示实际来源与输出设备；双开且检测到扬声器时提供一次非阻塞提示，不能偷偷关闭麦克风。无法确认输出设备类型时允许手选耳机/外放，标注未知而不是猜测。已有来源设置不静默迁移。外接扩音器也可能放大用户自己的声音，系统参考无法覆盖的声源不承诺消除。

### 3.1 技术方向与选型门禁

优先做停止后的本地派生处理，以已提交双原件为输入：时间对齐 → 以系统轨为参考估计麦克风中的回声 → 保留近端语音的麦克风派生信号 → 与系统轨混合 → 一条会议时间线进入现有 ASR。

- 先验证原生 AVAudioEngine/AUVoiceIO 能力，不能将 `setVoiceProcessingEnabled(true)` 等同于“能消除其他 App 外放”。原生链路对第三方声音的参考覆盖、离线双文件处理能力、声音压低和设备切换都是待验证条件。
- 不将捕获到的电脑声音重新播放去构造参考；避免双重播放、回授与改变会议体验。不因试验改变原轨采集承诺。
- 若原生方案不满足双原件派生处理，评估支持显式参考的本地 AEC。新增依赖前给出准确版本、许可证、替代方案和 ADR；非 MIT 须按项目规则另行确认。当前不指定未审查的第三方库。
- 需处理采集起始偏移、声学延迟、长时钟漂移、AAC 解码延迟、声道转换及音量突变；沿用 session 时间轴，不以墙钟猜对齐。
- 双方同时说话时保护近端，不能“系统轨有声音就静音麦克风”。低相关、无参考、削波或不确定段保留原内容并标记处理受限。
- 文本侧继续沿用 Qwen 输出质量门禁，不增加按相似句全局删除。VAD 降噪不能替代回声消除。

### 3.2 结果、失败与历史素材

- 一场会议仍是一条 Recording；用户默认看到一个会议回放和一个当前原文，原始双轨放在“原始文件”展开区。
- 成功结果注册为新的派生 Artifact，记录双父来源/摘要、算法版本、参数快照、处理状态、时间映射及质量指标。复用既有 Artifact 关系，Schema 需要扩展时附迁移测试。
- 不覆盖既有 meetingMix、原始音频或 Transcript。处理后的中间 PCM 默认临时使用，崩溃清理须限定在派生临时目录。
- 派生文件先写临时目标、校验后提交，再切换活动引用。失败保留可复听原件与既有合成；“使用普通合成继续转写”是明确动作，不能伪装为回声处理成功。
- 历史素材由用户选择“减少外放回声并重新转写”；先产生合格派生音频，再执行一次完整时间线转写并追加 Transcript 版本。不自动批量重处理。
- Job 幂等键包含输入摘要、处理版本和参数；取消/重启不产生多个活动合成或并发重复 ASR。保留 sourceSeparated 高级模式，明示外放重复和额外处理成本；本期不承诺修复其跨轨文字合并。

## 4. 视觉与组件设计

布局草图（表示关系，不代表最终像素验收）：

```text
┌ 左栏 264–320 pt ───┬ 内容列 ──────────────────────────────┐
│ 素材库 / 处理任务  │ ● 正在录音  03:24  双音源 [结束并保存]│
│ 文字转音频         │ 实时预览 ▾                            │
│ 搜索素材   筛选    ├──────────────────────────────────────┤
│ 今天              │ 当前会话，或用户选中的素材详情         │
│   素材标题        │ 标题 / 录音信息                        │
│   来源·时长·时间   │ 回放条                                 │
│ 昨天              │ 原文 / 处理结果                        │
│   素材标题        │ 可滚动正文                             │
│ 设置              │                                        │
└───────────────────┴────────────────────────────────────────┘
```

- 保留单侧栏。工作区导航收紧为 32–36 pt 行高，下方列表独立滚动；设置固定底部。侧栏默认 288 pt，允许 264–320 pt 拖动。
- 列表每行标题最多两行、元数据一行；就绪只保留一个克制的“已就绪”标签，不同时出现绿色图标和重复绿色句子；失败明确“转写失败 · 原件已保存”，仅在持久化事实成立时显示后半句。
- 使用系统列表背景和选中态；先验证灰底来自容器还是非活动窗口状态，再调整。不得用固定白色覆盖以破坏深色模式。
- 搜索采用原生控件，保留真实键盘焦点环；筛选为紧凑菜单。导入图标加 tooltip/VoiceOver，删除进入选中素材的动作菜单，降低误触。
- 正文约 15–16 pt、标题 20–24 pt、次要信息 12–13 pt；4 pt 网格，容器内边距 16–24 pt，圆角 8–12 pt。系统字体和语义颜色优先，减少厚边框、大灰块、额外阴影。
- 录音状态区、反馈和实时文字按正常垂直布局排列；滚动正文不能滚走停止按钮。窄窗将来源摘要折为菜单，保持结束按钮完整文字；800×560 下无横向溢出，必要时用户可收起侧栏。
- 不用假波形；若呈现电平，复用真实音源活动数据且降低刷新频率。Reduce Motion 关闭装饰动画。高对比、非颜色状态、VoiceOver、键盘焦点顺序必须实测。

复用 SwiftUI + AppKit、AppState、WorkspaceRouter、LiveTranscriptPreviewCard、现有列表行与语义样式。菜单栏/工作台共用轻量录音状态投影和动作按钮；会话布局仍各自适配。音频派生复用 AudioPreparationService、Job/Artifact 存储和现有后台执行边界，UI 不直接操作文件、音频引擎或数据库。不启动全仓模块重构或新的设计系统。

## 5. 验收标准（目标，尚未执行）

| ID | 验收 |
|---|---|
| REC-01 | 主界面开始→准备→录音→停止→保存→转写状态完整；录音时无误导开始按钮；主窗口内一次点击可停止 |
| REC-02 | 选中旧素材、切工作区、收侧栏、关闭预览、重开窗口，停止入口与计时一致；双窗口并发停止只提交一次 |
| REC-03 | 保存失败、权限拒绝和设备中断有准确状态；原件/历史 Artifact 摘要不变；未落盘不展示已保存 |
| ECHO-01 | 无隐私夹具覆盖远端单讲、近端单讲、双方重叠、真实复述、静音、噪声、延迟、漂移和削波；固定模型及参数比较普通/处理后混音 |
| ECHO-02 | 远端单讲可控夹具的稳定段 ERLE 中位数 ≥10 dB；近端单讲电平变化 ≤1 dB；这些是准入目标，不是已有能力声明 |
| ECHO-03 | 真实人工标注样本中非原话重复字数/参考字数 ≤1%，且相对普通混音下降 ≥80%（基线足够高时）；近端及双讲 CER 各不得劣化超过 2 个百分点，真实复述保留 |
| ECHO-04 | 内置扬声器、外接扩音器、有线/蓝牙耳机和真实会议 App 验证；不改变播放内容、不引入二次播放；跨设备未通过不宣称通用支持 |
| ECHO-05 | 60 分钟固定夹具派生处理 RTF ≤0.3、增量峰值 RSS ≤300 MiB，提交后总时长偏差 ≤100 ms；精确时间映射可追溯，UI 不阻塞；设备/系统/版本随报告记录 |
| ECHO-06 | 开启处理时每次重转写只消费一条派生时间线；原件和旧版本不变；失败/取消/重启无破损激活引用、无静默丢轨 |
| UI-01 | 800×560、1180×760、宽窗、明暗/高对比/非活动窗口无遮挡；停止目标 ≥32 pt，键盘与 VoiceOver 可操作 |
| UI-02 | 用户能在 3 秒内判断是否录音、录什么、在哪里结束；2 人均停顿超过 3 秒即不通过；未做盲测不得声明通过 |

ERLE 只用于有可控参考的远端单讲段，不作为双讲保真指标；真实录音须结合参考文字和复听。若 ECHO 门禁未通过，可独立交付 REC/UI 与来源提示，回声开关保持不发布，不能削弱门槛后标完成。

## 6. 与旧规格的裁决

- 保留 2026-09-07 MSP 的默认单次转写和原始双轨；纠正其“单次转写/无回声重复”的过度承诺，单次不保证无声学回声。
- 启动实施后，本文替代 2026-08-25 视觉层级规格中“工作台不显示录音控制”的绝对限制；菜单栏继续保留控制，两处共享状态。
- MRQ 已完成代码不重开；新增 REC/ECHO/UI 工作由新计划独立承接。MRQ 的 Qwen tokenizer/重复生成、耐久性和 TCC 等未完成验收仍归原计划，不迁走或虚假结项。

## 7. 调研来源与推断限制

- [Apple：What’s new in voice processing](https://developer.apple.com/videos/play/wwdc2023/10235/)：原生语音处理包括回声消除，并存在其他音频 ducking 行为；对 Woice 第三方会议参考覆盖的适用性仍需 Spike 验证。
- [Apple：setVoiceProcessingEnabled](https://developer.apple.com/documentation/avfaudio/avaudioionode/setvoiceprocessingenabled(_:))：原生候选入口，不代表离线双文件 AEC 已可用。
- [Apple：excludesCurrentProcessAudio](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/excludescurrentprocessaudio)：排除本 App 播放的捕获内容，不是消除麦克风中的外放回声。

## 8. REC-01 实施结果（2026-09-14）

- 工作台内容列顶部新增共享 AppState 的录音会话控制区；切换素材库、处理任务、文字转音频、设置或收起侧栏后，停止入口仍在工作台内可见。
- 录音中主操作显示“结束并保存”，点击调用现有 AppState.stopRecording()；没有新增 UI 自维护的录音状态或计时器。
- 实时文字预览改为控制区下方的正常布局，不再覆盖停止入口或主体内容。
- WorkspaceRecordingSessionPresentation 提供开始/停止文案、图标和辅助功能提示，并由 WorkspaceRecordingControlsTests 覆盖。
- 证据：swift test --no-parallel --filter WorkspaceRecordingControlsTests 通过；make test 通过（286 项、18 个套件）；make lint 和 make xcode-build-direct 通过。
