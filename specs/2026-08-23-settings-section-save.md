# 设置分区独立保存

## 目标

设置页的录音与输入、模型与转写、文件与隐私分别保存。保存某一分区时，只提交该分区的草稿字段；其他分区的未保存草稿留在当前窗口，不参与校验、Keychain 写入或运行时路由更新。

## 范围

- 录音与输入：语言、自动复制/粘贴、时间戳、实时预览、快捷键、系统声音与会议转写方式。
- 模型与转写：ASR 配置、已选本机模型、ASR/LLM Endpoint、模型和 API Key。
- 文件与隐私：导出目录。
- 每个分区使用“保存本页”和“还原本页”；未保存草稿切换分区或关闭窗口时不隐式提交。

## 不变约束

- API Key 只在模型与转写分区的密钥字段发生变化时写入 Keychain。
- 保存其他分区不读取、不写入、不删除 Keychain。
- 原始录音、Artifact、Job 和当前模型不会因设置保存失败而改变。
- 保存失败时该分区草稿保持未保存状态，已持久化设置与其他分区草稿不回滚。

## 验收标准

- AC-001：仅修改录音分区并保存，持久化录音字段变化；Keychain 访问日志为空。
- AC-002：仅修改文件分区并保存，持久化导出目录；ASR/LLM 配置和 Keychain 不变。
- AC-003：模型分区保存 API Key 时只写入发生变化的账号；其他 API Key 不被触碰。
- AC-004：其他分区存在非法草稿时，保存当前合法分区仍可成功；非法草稿留在界面等待用户处理。
- AC-005：分区保存失败时，当前运行设置不改变，按钮反馈失败且草稿可继续修改。
- AC-006：`make acceptance-settings`、`make test`、`make docs-check`、`make harness-check` 和 `make lint` 通过。

## 设计决策

Core 的 `AppSettingsScope` 定义分区字段边界；`AppState.saveSettings` 接受可选范围，在持久化前将范围外字段替换为当前已提交设置。UI 维护整页草稿，但保存/还原只更新活动分区基线。这样不新增第二套设置模型，也不会让一个分区的草稿污染另一个分区的保存事务。
